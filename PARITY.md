# DepoAudio Parity Contract

Baseline: `main @ 0047549` (v0.8.0 lineage, 2026-07-02).

This document is the inventory of behavior that installed users depend on.
Any refactor, redesign, or rebuild must preserve everything listed here unless
a change is deliberate and called out in the changelog. The characterization
test suite (see [Test index](#test-index)) mechanically enforces the starred
(★) items. Release automation separately verifies native FTR decoding, zero
learned-model distribution, and bounded packaged application startup. Every
other capability requires the manual installed-app checks in
[`docs/V1.1.0-RELEASE-CANDIDATE.md`](docs/V1.1.0-RELEASE-CANDIDATE.md); a green
automated smoke test is not evidence that the complete capability map was
exercised.

## IPC surface

The de-facto API between the React frontend and the Rust core. Names,
argument shapes (camelCase), and return shapes are all contract.

| Command                                                                                  | Contract notes                                                                                                                                                                                                                                     |
| ---------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `health_check`                                                                           | Executes both sidecars with `-version`, verifies the exact native FTR decoder, and returns `{ffmpeg, ffprobe, ftrDecoder, ffmpegVersion, os, arch}`; `ffmpegVersion` is only the first-line version token (or null) so "Copy diagnostics" never carries a path |
| `get_formats_list` / `detect_format` ★                                                   | Format registry incl. status/handler/notes; detection by extension, plus a TIFF-header check for `.dcr` (see helpers tests)                                                                                                                                                             |
| `infer_case_name_cmd` ★                                                                  | Strips date patterns, underscores → spaces                                                                                                                                                                                                         |
| `begin_conversion_batch_cmd`, `cancel_conversion_cmd`, `convert` ★                       | Generation-based cancellation is serialized with the final output/library commit. `convert` emits progress, done (including warnings), cancelled, or error events; event-delivery failures reject instead of leaving the frontend waiting forever. |
| `analyze_audio_cmd`, `cancel_scan_cmd`                                                   | `AnalysisResult` (camelCase); analysis is cancellable and bounded to a 180 s sample (`ANALYSIS_SAMPLE_SECS`)                                                                                                                                       |
| `waveform_peaks_cmd`                                                                     | Produces a bounded fixed-size peak envelope through the FFmpeg sidecar; browser code never decodes the full recording                                                                                                                              |
| `system_capabilities_cmd`                                                                | Reports conservative local CPU/system information and learned-processing availability as false                                                                                                                                                    |
| `legacy_model_cleanup_catalog_cmd`, `delete_legacy_model_cmd`                            | Lists and deletes only exact allowlisted regular legacy files in app-data; there is no download, install, resolution, or execution path                                                                                                            |
| `detect_cat_software_cmd`, `scan_cat_jobs_cmd`                                           | Recursive filesystem work runs on the blocking pool; depth clamped 1–20 (default 5)                                                                                                                                                                |
| `detect_sync_cmd`, `merge_audio_cmd`                                                     | Not registered while Merge is hidden (the release contract fails if they return to `invoke_handler`); `merge.rs` stays compiled and unit-tested |
| `library_get` ★                                                                          | Returns the startup-loaded in-memory library or a durable-load error; corrupt storage disables mutations instead of appearing empty                                                                                                                |
| `library_rename_case`, `library_archive_case`                                            | Persist a candidate atomically before publishing it in memory; return whether a matching case changed                                                                                                                                              |
| `library_delete_case`, `library_delete_session`                                          | Return `{changed, warning}` so a committed deletion is not misreported as failed if ephemeral playback revocation fails                                                                                                                            |
| `library_import_file`, `library_import_files` ★                                          | Canonical, playable local audio paths only; multi-file validation and persistence are atomic; case name sanitized (≤200 chars), label ≤100 chars, and an archived target case is re-activated. Returns `{changed, warning}`.                       |
| `prefs_get` / `prefs_set` ★                                                              | Patch-merge on known top-level camelCase keys; unknown keys, non-object patches, and type-invalid updates fail explicitly without changing disk or memory                                                                                          |
| `show_in_folder`                                                                         | Reveals path via opener plugin                                                                                                                                                                                                                     |
| `local_data_info_cmd`                                                                    | Returns `{appDataDir, items[{name, kind, bytes}], libraryReadable}`; lists only DepoAudio's own regular files (`library.json`, `prefs.json`, `library.tmp.*`/`prefs.tmp.*` from atomic writes, allowlisted `models/` legacy files) |
| `local_data_clear_cmd`                                                                   | Refuses while a conversion is running; removes exactly the files `local_data_info_cmd` lists (never a symlink, folder, anything in a symlinked `models` folder, or any path recorded in the Library), resets in-memory library and prefs and their load-error markers, revokes playback access; returns `{removed, warning}` |
| `local_data_export_cmd`                                                                  | `{path, transcripts, bookmarks}` → a new `.zip` (`create_new`, never replaces) of stored entries `depoaudio-backup.json`, `README.txt`, `library.json`, `transcripts.json`, `bookmarks.json`; ≤ 64 MiB; refuses an unreadable library; returns counts |
| `local_data_import_cmd`                                                                  | Reads only an unmodified backup (known stored entries, CRC-32, format marker and version); validates every case name and audio extension first, then adds missing cases (by name) and sessions (by ID) atomically; authorizes playback only for a resolved regular audio file; returns `{casesAdded, sessionsAdded, sessionsSkipped, filesUnavailable, filesNeedRestart, transcripts, bookmarks}` |

## Processing contracts (audio output)

These define what converted files sound like. Changing them changes output
for identical inputs — never do it silently.

- ★ Filter order: de-clip → high-pass → auto-level gain → loudnorm → source-relative fade-out → leading trim → fade-in (`proc_filters` tests).
- ★ Stereo mode: unity-gain SUM of all channels on both L/R via `aformat=sample_fmts=fltp` (mix in float, so a sum past full scale cannot wrap) + `pan=stereo` + `volume=N` compensation; `alimiter=limit=0.97:level=false:latency=1` appended when normalize is off (peak guard for correlated content; `latency=1` cancels the limiter's 5 ms lookahead delay so the mix lines up sample for sample with the source).
- ★ Split mode: `asplit` + `pan=mono|c0=cN` per channel (NOT `channelsplit`, which assumes a stereo layout); auto-level injects each channel's own gain right after isolation; near-unity gains (±0.01) skipped.
- ★ Keep Original mode rejects auto-leveling at the backend boundary; one shared gain cannot perform the documented per-channel balancing while preserving the channel layout.
- ★ MP3 bitrates limited to 128/192/320 kbps, off-menu values fall back to 192.
- Opus always encodes 64k VBR at 48 kHz; m4a AAC 128k.
- ★ WAV: 16-bit PCM in a plain RIFF header (`fmt ` straight after `WAVE`, as 1.1.0 wrote). A WAV whose estimated size (converted-stream duration × channels per output × output rate × 2 bytes) reaches 3.5 GiB, or cannot be estimated, also gets `-rf64 auto`: FFmpeg then writes RIFF with a reserved JUNK chunk while the file fits, and RF64 once it passes 4 GiB (`wav_rf64_args` in `helpers.rs`). The export record's `output.wavHeader` is read from the finished file's first four bytes (`riff` or `rf64`); any other header fails the conversion. Convert shows an estimated WAV size (duration × channels × sample rate × 2 bytes) from the queue probe.
- SGMCA: the stream starts at the first CRC-correct beginning-of-stream Ogg page carrying `OpusHead` within the first 8 KiB; a file that starts there at byte 0 is used in place, otherwise the bytes before it are stripped into a temporary `.sgmca` copy (blocking pool, cancellation checked every 64 KiB). No Ogg marker, a marker without a readable Opus header, or another codec each get their own message. SGMCA inputs are decoded with `-c:a libopus`. SGMCA output: libopus, mapping family 255, 20 ms frames, `-ar 16000`, 32 kbps per mono stream, `-f ogg`; each output is read back and must have one uncoupled mono stream per channel with identity mapping, or it is removed.
- FTR/TRM/TLL (`trm.rs`; layout from the owner's interoperability notes, checked against one sample made by the owner's rebuild tool, `scripts/fixtures/trm/vendor-notes-samples/`, never against a recording made by FTR): the format tag's low 12 bits name the codec; 0x180 (FTR AAC) needs bit 0x4000 (N = nChannels mono streams) or 0x8000 (N = nChannels / 2 stereo streams) and is otherwise refused ("This FTR recording's format isn't one FTR's own player can split, …", by every route, queue included); MP2 (0x50), MP3 (0x55) and WMA (0x160–0x163) go to FFmpeg as they are (`decodePath` `ffmpeg-plain`, a codec-naming message if FFmpeg cannot decode them). The number of `strl` lists counts, not avih dwStreams; level-meter (`NNal`) chunks and everything after idx1 are skipped (SIGN/CERT is reported as `signature: "signed (not verified)"`, never checked or written). TUTC/TLOC give `startUtc`/`startLocal`; TLOC's time of day (else TUTC's, else the FILETIME in the FILE chunk's name) is the start (`startTime.source` `ftr-tloc`/`ftr-tutc`/`ftr-file-name`); only a TLOC start (local time, as bext counts it) is written into WAV outputs' bext time reference, the others are kept in the record only. USER and UDAT text is never recorded, logged or shown: only `userNamePresent`/`userDataPresent`; the FILE text is recorded as `recordedFileName` only when it is a name in the recorder's format (name part of at most 28 allowed characters, `_YYYYMMDD-HHMM_` matching the 16-hex FILETIME, extension), otherwise only `recordedFileNamePresent`; presence counts any chunk with text anywhere in it. For FTR AAC, every probe, Scan, auto-level pass, waveform, merge decode, queue probe and conversion first reads the recording through (64 KiB buffered reads that move forward inside the buffer, so each pass reads the file about once; never changed) and reports channels, sample rate (first stream-0 ADTS header), start/end boundary flags, open-ended length, index kind (`idx1-absolute`, `idx1-relative` or `walked`; the first idx1 entry of any type picks relative or absolute and the other is tried if it does not match), chunk and frame counts, scrambled, cross-chunk, misaligned and several-rounds-per-chunk counts, bytes before channel 0, channel-order restarts, mid-stream, padding and trailing bytes skipped, frames dropped, frames with the two ADTS length bits FTR ignores, truncation, RIFF AVIX continuation segments, the FTRA values and video stream count. A zero-size (never closed) idx1 runs to EOF and is not truncation. The channel marker (ADTS private bit) is checked on every frame: a round must open with a clear bit and, once the file has shown that it sets the bit on other channels, a clear bit inside a round starts a new round; on a mismatch the partial round is dropped and dealing restarts at the next channel-0 frame. The file goes to FFmpeg's native `-c:a ftr` decoder as it is only when every audio chunk holds exactly one round starting at channel 0, the file is indexed, closed and not truncated, nothing was skipped, padded, dropped or restarted, no frame has those length bits or a channel count other than the tag declares, and the decoder is present (0x4180 and 0x8180 alike). Otherwise, or when the native decoder fails a conversion, every Scan loudness pass, a waveform or a merge/sync decode, each stream is written to a temporary ADTS file (descrambled, length bits cleared, equal frame counts) in a new folder per conversion (`depoaudio_trm_run_<32 hex>` inside this run's private work folder, `workdir.rs`, created fresh, never reused, 0700 with 0600 files on Unix), and FFmpeg reads the N files (one per stream: mono, or stereo holding channels 2k and 2k + 1; a per-channel Scan pass reads only the file holding that channel) joined in channel order with `[0:a:0]…[N-1:a:0]amerge=inputs=N` (in `-filter_complex`, with any chain appended, mapped as `[da_out]`; split mode splits `[da_src]`). A folder left by a killed run goes with its run folder in the work-folder sweep (at launch and on "Clear all DepoAudio data"). An idx1 that misses audio chunks (one after the last listed, or a count other than dwLength/FTRA d in a closed file) blocks native (`index-misses-audio-chunks`, `indexMismatch`) and the movi walk is used when it finds more. The walk looks up to 4 MiB past an unreadable header, zero gap or missing pad byte for the next `00wb` with an FTR frame header (`walkGaps`, `walkGapBytes`). Dropped partial rounds are not filled with silence; `droppedRounds`/`timelineShiftSecs` and `startTime.note` state the shift. The split reads no further than the inspection did, so a recording still being written converts as inspected (`grewWhileRead`). A file with AVIX segments is not split. A file DepoAudio cannot read, or in which it finds no complete round to split, goes to the native decoder as it is when that is present (`source.trmInspectionError`). Durations come from the frames read, never from an unclosed file's 0x7FFFFFFF length. The export record's optional `source.trm` holds the inspection with `decodePath` (`native-ftr`, `deinterleaved` or `ffmpeg-plain`), `routeReasons`, `inputOptions` and `inputCount`. A synthetic 4-channel fixture with one round per chunk, a synthetic 0x8180 file of two stereo streams, and the rebuild-tool sample (245 760 silent samples per channel) each decode to bit-identical samples by both routes with FFmpeg 6.1.1; with two rounds per chunk that FFmpeg's native decoder wrote an M4A about half as long without an error, which is why such files are split.
- FTR queue notices: an open-ended file says "This recording's header says it was never closed (or is still recording); DepoAudio read the audio written so far."; a signed one "This recording carries a signature: signed (not verified). DepoAudio does not check signatures."; MP2/MP3/WMA audio names its codec; a refused file shows the refusal. Queued chunks with the same folder and location in the canonical FTR name, on the same or consecutive dates, are sorted by the FILETIME in their names and cut into recordings at the avih boundary flags (0x20000000: no earlier file may be joined; 0x40000000: no later file may be joined); once all are read, a recording whose earliest queued file has no start boundary says "The earliest queued file of this recording has no start-boundary mark, so FTR would accept earlier files before it; if there are any, add them too." (and the same for the latest file and the end boundary). A `.trs` session list is not queued; a notice asks for the FTR chunks instead (unchanged).
- ★ Audio stream: every ffprobe call, Scan and auto-level pass, waveform decode, merge decode and conversion reads the first audio stream explicitly (`-select_streams a:0`, `-map 0:a:0`, split filtergraph input `[0:a:0]`; `SOURCE_AUDIO_STREAM` in `helpers.rs`). The export-record probe and the queue probe list every audio stream (`-select_streams a`) so they can count them, and read the converted stream as the first entry. The fade-out start comes from a decoded-length pass (`decoded_length_args`: the same inputs, decoder and `-map 0:a:0`, or the `amerge` of an FTR recording's channel files, `DECODED_LENGTH_FILTER` counting samples at 48 kHz), never from a stated duration, and the export record keeps both in `processing.fadeOut`. Durations for the WAV size estimate and progress are the converted stream's own (`duration`, or the Matroska `DURATION` tag), falling back to the container duration only when the stream has none. FFmpeg's automatic selection is never used: it prefers a track marked default, then the one with the most channels, which can differ from the stream the probes and the export record describe. A queued file with more than one audio track names the converted track in its row (SGMCA files are not probed in the queue).
- Export record: each output is reserved together with `<output>.depoaudio.json` (both `create_new`; a taken name moves both to the next numbered name), and the record holds file names only, source and output SHA-256, app version, the exact filter chain, `-map` arguments (`processing.mapArgs`) and encoder arguments, channel and label, the converted audio stream with the source's audio stream count (`audioStream`), the WAV header written (`output.wavHeader`), and the start time. If the record cannot be written, the conversion fails and its outputs are removed.
- Start time: a BWF `bext` TimeReference from a WAV source (the `wav` demuxer, RF64 included; tags in other containers are ignored) is rescaled to the output sample rate and written to WAV outputs with `-write_bext 1`. Every other output gets `-metadata time_reference=`, which removes the tag FFmpeg would copy unrescaled into FLAC, MP3 and Opus, so the start is then in the export record only. Leading-silence trim (not split mode) moves the start, so it is then recorded as not carried and the output has no start tag.
- Learned processing flags are compatibility-only wire fields. Any request with `denoise`, `enhance`, or `dereverb` set fails before file preparation or decode.
- Analysis and auto-level use at most a 180-second representative sample; every sidecar call has a timeout and a kill path (the fix for the scan-hang bug, PR #52).

## Release / update channel

- GitHub Actions `release.yml` creates one commit-bound private draft, builds universal macOS and Windows installers sequentially, stages reviewed FFmpeg inputs, proves zero learned-model/ONNX Runtime payloads, generates and normally decodes a transient synthetic 440 Hz FTR-tagged fixture with the exact candidate sidecars, and uploads only through an exact-draft verifier. `scripts/ftr-smoke-fixture.mjs` keeps the fixture and derived outputs under the runner's temporary directory and removes them before packaging; artifact inventories still reject every `.trm` file. Tauri's action is build-only and has no release mutation credentials.
- Updater artifacts are generated only when the configured private/public keys cryptographically match. Platform signing is enabled independently when that platform's credentials are present; otherwise the workflow produces an ad-hoc-signed macOS app or unsigned Windows installers. Updater key/endpoint configuration is generated only inside the release job; local builds contain neither placeholders nor a live update endpoint.
- Existing published asset names and bytes are immutable. The candidate workflow may reuse only one empty same-tag draft already bound to the exact source commit and retaining the canonical name, changelog notes, and prerelease state; it rejects stale, populated, altered, or duplicate drafts instead of deleting them, never modifies a published release, and finalizes only by auditing the complete private draft. The audit receives the release access GitHub requires to read a private draft, but the release contract rejects mutation commands in that job. The workflow canonicalizes Tauri's updater archive to the versioned universal release name before hashing and upload. It deliberately rejects `latest.json`; updater metadata and publication require a separate approval gate bound to the exact release ID, source commit, assets, signing decision, and release date.
- `publish-release.yml` separates read-only candidate-manifest inspection from protected publication. Its publication path checks out the immutable approval commit, re-downloads and verifies the complete candidate and evidence inventory, cryptographically validates signed updater artifacts, records both source and approval commits, verifies the owner's signed release tag at the source commit (it never creates or moves a tag), and publishes only the approved release ID. The `release-publication` environment's 24-hour wait timer and `main`-only deployment policy, and the tag ruleset that protects `v*` tags, must be verified in GitHub because repository source cannot prove dashboard policy; the workflow reads them back and fails closed.
