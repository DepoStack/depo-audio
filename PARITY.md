# DepoAudio Parity Contract

Baseline: `main @ 0047549` (v0.8.0 lineage, 2026-07-02).

This document is the inventory of behavior that installed users depend on.
Any refactor, redesign, or rebuild must preserve everything listed here unless
a change is deliberate and called out in the changelog. The characterization
test suite (see [Test index](#test-index)) mechanically enforces the starred
(★) items. Release automation separately verifies native FTR decoding, zero
learned-model distribution, and bounded packaged application startup. Every
other capability requires the manual installed-app checks in
[`docs/V1.2.0-RELEASE-CANDIDATE.md`](docs/V1.2.0-RELEASE-CANDIDATE.md); a green
automated smoke test is not evidence that the complete capability map was
exercised.

## IPC surface

The de-facto API between the React frontend and the Rust core. Names,
argument shapes (camelCase), and return shapes are all contract.

| Command                                                                                  | Contract notes                                                                                                                                                                                                                                     |

| `get_formats_list` / `detect_format` ★                                                   | Format registry incl. status/handler/notes; detection by extension, plus a signature check for `.dcr` (Liberty / BIS `HGCRLCRS`, TIFF camera image, or neither; see helpers tests)                                                                                                                                                             |

## Processing contracts (audio output)

These define what converted files sound like. Changing them changes output
for identical inputs — never do it silently.

- ★ Filter order: de-clip → high-pass → auto-level gain → loudnorm → source-relative fade-out → leading trim → fade-in (`proc_filters` tests).
- ★ Stereo mode: unity-gain SUM of all channels on both L/R via `aformat=sample_fmts=fltp` (mix in float, so a sum past full scale cannot wrap) + `pan=stereo` + `volume=N` compensation; `alimiter=limit=0.97:level=false:latency=1` appended when normalize is off (peak guard for correlated content; `latency=1` cancels the limiter's 5 ms lookahead delay so the mix lines up sample for sample with the source).
- ★ Split mode: `asplit` + `pan=mono|c0=cN` per channel (NOT `channelsplit`, which assumes a stereo layout); auto-level injects each channel's own gain right after isolation; near-unity gains (±0.01) skipped.
- ★ Keep Original mode rejects auto-leveling at the backend boundary; one shared gain cannot perform the documented per-channel balancing while preserving the channel layout.
- ★ MP3 bitrates limited to 128/192/320 kbps, off-menu values fall back to 192.
- Opus always encodes 64k VBR at 48 kHz; m4a AAC 128k.
- ★ WAV: 16-bit PCM in a plain RIFF header (`fmt ` straight after `WAVE`, as 1.0.2 wrote). A WAV whose estimated size (converted-stream duration × channels per output × output rate × 2 bytes) reaches 3.5 GiB, or cannot be estimated, also gets `-rf64 auto`: FFmpeg then writes RIFF with a reserved JUNK chunk while the file fits, and RF64 once it passes 4 GiB (`wav_rf64_args` in `helpers.rs`). The export record's `output.wavHeader` is read from the finished file's first four bytes (`riff` or `rf64`); any other header fails the conversion. Convert shows an estimated WAV size (duration × channels × sample rate × 2 bytes) from the queue probe.
- ★ SGMCA (layout from owner-supplied interoperability notes; not yet confirmed against a file CATalyst wrote; see `docs/SGMCA.md`): a 40-byte file header (size 40, version 1, recording identifier, reserved) then one segment per recording session (56-byte header: size 56, version 1, kind 2, local start text `YYYY-MM-DDTHH:MM:SS±hhmm`, u64 payload length) holding a complete Ogg Opus stream. Any other file header size or version is refused; a segment header below 56 bytes is refused, while a larger one, or another segment version or kind (which the notes say CATalyst does not check), is read and noted; a file starting with `OggS` is read as the older bare-Ogg layout and named so. Segments are walked by payload length with strict bounds; every page's CRC is checked; families 255 and 1 (one uncoupled stream per channel, identity mapping) and 0 are read; every session must have the same channel count and stream layout (a different output gain is noted); a page granule past the end of its packets, or beyond the signed 64-bit range, is refused; a file whose sessions hold no samples is refused. A page of a second logical stream inside a segment before its end-of-stream page is refused. A last segment shorter than its header, or bytes no header counts, are read up to the last complete page and flagged `growing`; a last session that ends before its Opus headers or holds no audio page yet is left out; every session left out (`zero-length-header`, `no-complete-audio`, `empty`) and the bytes not read are recorded (`source.sgmca.omittedSegments`, `unreadBytes`) and named in the queue before converting; uncounted pages followed by another session's header refuse the file rather than drop that session. The two sample files that came with the notes (made by the owner's tool, not CATalyst) are committed under `scripts/fixtures/sgmca/vendor-notes-samples/` and tested. Sessions are joined in file order with no gap: FFmpeg reads a temporary concat script whose `subfile` entries point at each session's byte range of the original (no audio copy; `-f concat -safe 0 -protocol_whitelist file,subfile`, `feed_format_args` in `helpers.rs`), with each session's exact duration; bare Ogg is read in place. SGMCA inputs are decoded with `-c:a libopus`. SGMCA output: libopus, mapping family 255, 20 ms frames, `-ar 48000`, 32 kbps per mono stream, `-f ogg`, then wrapped in the file header (fresh UUID v4) and one segment per source session (cut without re-encoding at each session's start sample) or one segment; start times from the source's segment headers (never an unparseable one: that falls back to the conversion time), else BWF date + bext time reference (the whole second at or before the first sample, every source sample kept, the fraction recorded as `startOffsetMs` and in the note; this computer's offset), else the conversion time (an FTR recording's own start stays in `source.trm` and is not written into segment headers), and conversion time whenever leading-silence trim ran on a one-session source (trim on a source with more than one session is refused, for every output format); each output is read back and must have the header, complete segments with the planned, parseable starts and family 255 with one mono stream per channel, and, from an SGMCA source without trim, exactly the source's samples in total and per session, or it is removed; a chain with `alimiter` lacking `latency=1` (a 5 ms delay at the same length) is refused for SGMCA output (the `amerge` joining an FTR recording's channel files is measured in place and allowed). The export record adds optional `source.sgmca` and `output.sgmca` objects (never the identifier itself). The slicer (library only) refuses a cut that spans two sessions and cuts exactly at the requested start, writing the whole second at or before it with the fraction reported as `startOffsetMs`; the writer refuses a plan whose first segment does not start at the first sample, so no encoded audio is left out.
- FTR/TRM/TLL (`trm.rs`; layout from the owner's interoperability notes, checked against one sample made by the owner's rebuild tool, `scripts/fixtures/trm/vendor-notes-samples/`, never against a recording made by FTR): the format tag's low 12 bits name the codec; 0x180 (FTR AAC) needs bit 0x4000 (N = nChannels mono streams) or 0x8000 (N = nChannels / 2 stereo streams) and is otherwise refused ("This FTR recording's format isn't one FTR's own player can split, …", by every route, queue included); MP2 (0x50), MP3 (0x55) and WMA (0x160–0x163) go to FFmpeg as they are (`decodePath` `ffmpeg-plain`, a codec-naming message if FFmpeg cannot decode them). The number of `strl` lists counts, not avih dwStreams; level-meter (`NNal`) chunks and everything after idx1 are skipped (SIGN/CERT is reported as `signature: "signed (not verified)"`, never checked or written). TUTC/TLOC give `startUtc`/`startLocal`; TLOC's time of day (else TUTC's, else the FILETIME in the FILE chunk's name) is the start (`startTime.source` `ftr-tloc`/`ftr-tutc`/`ftr-file-name`); only a TLOC start (local time, as bext counts it) is written into WAV outputs' bext time reference, the others are kept in the record only. USER and UDAT text is never recorded, logged or shown: only `userNamePresent`/`userDataPresent`; the FILE text is recorded as `recordedFileName` only when it is a name in the recorder's format (name part of at most 28 allowed characters, `_YYYYMMDD-HHMM_` matching the 16-hex FILETIME, extension), otherwise only `recordedFileNamePresent`; presence counts any chunk with text anywhere in it. For FTR AAC, every probe, Scan, auto-level pass, waveform, merge decode, queue probe and conversion first reads the recording through (64 KiB buffered reads that move forward inside the buffer, so each pass reads the file about once; never changed) and reports channels, sample rate (first stream-0 ADTS header), start/end boundary flags, open-ended length, index kind (`idx1-absolute`, `idx1-relative` or `walked`; the first idx1 entry of any type picks relative or absolute and the other is tried if it does not match), chunk and frame counts, scrambled, cross-chunk, misaligned and several-rounds-per-chunk counts, bytes before channel 0, channel-order restarts, mid-stream, padding and trailing bytes skipped, frames dropped, frames with the two ADTS length bits FTR ignores, truncation, RIFF AVIX continuation segments, the FTRA values and video stream count. A zero-size (never closed) idx1 runs to EOF and is not truncation. The channel marker (ADTS private bit) is checked on every frame: a round must open with a clear bit and, once the file has shown that it sets the bit on other channels, a clear bit inside a round starts a new round; on a mismatch the partial round is dropped and dealing restarts at the next channel-0 frame. The file goes to FFmpeg's native `-c:a ftr` decoder as it is only when every audio chunk holds exactly one round starting at channel 0, the file is indexed, closed and not truncated, nothing was skipped, padded, dropped or restarted, no frame has those length bits or a channel count other than the tag declares, and the decoder is present (0x4180 and 0x8180 alike). Otherwise, or when the native decoder fails a conversion, every Scan loudness pass, a waveform or a merge/sync decode, each stream is written to a temporary ADTS file (descrambled, length bits cleared, equal frame counts) in a new folder per conversion (`depoaudio_trm_run_<32 hex>` inside this run's private work folder, `workdir.rs`, created fresh, never reused, 0700 with 0600 files on Unix), and FFmpeg reads the N files (one per stream: mono, or stereo holding channels 2k and 2k + 1; a per-channel Scan pass reads only the file holding that channel) joined in channel order with `[0:a:0]…[N-1:a:0]amerge=inputs=N` (in `-filter_complex`, with any chain appended, mapped as `[da_out]`; split mode splits `[da_src]`). A folder left by a killed run goes with its run folder in the work-folder sweep (at launch and on "Clear all DepoAudio data"). An idx1 that misses audio chunks (one after the last listed, or a count other than dwLength/FTRA d in a closed file) blocks native (`index-misses-audio-chunks`, `indexMismatch`) and the movi walk is used when it finds more. The walk looks up to 4 MiB past an unreadable header, zero gap or missing pad byte for the next `00wb` with an FTR frame header (`walkGaps`, `walkGapBytes`). Missing rounds are filled with frames that add no new sound: at each channel-0 frame that opens a round, the fewest whole rounds that hold the frames seen since the previous one (frames taken as lost, never as added), less the round delivered, go into every stream file as AAC frames with an empty spectrum (one single-channel or channel-pair element, no scale factor bands) just before the next round delivered, so every channel keeps the full timeline; nothing goes after the last whole round. Each place is in `silenceFilled` (`atSample` from the first frame delivered, `samples`, `channels`, `reason` `missing-frames`, or `unreadable-data` where skipped bytes or a walk gap were also there; at most 1000 listed, `silenceFilledGaps` and `silenceFilledSamples` count all), `durationSecs` includes it, route reason `silence-filled`, `startTime.note` says so, and the queue says "N damaged sections were filled to keep the timing, adding no new sound (the sound just before each fades out across it); see the export record." Unreadable data still leaves an unknown length (`startTime.note`: "by an unrecorded amount"), and frames missing in a run as long as a whole round cannot be seen. Tests with click tracks encoded by FFmpeg 6.1.1 (a missing channel-2 frame, a round cut after channel 1, a missing channel-0 frame) decode to the intact file's length on every channel and, for that encode (no PNS), to samples bit-identical to the intact file outside the two decoded stretches the lost frames overlapped, so every later click is on its true sample; a tone test shows the filled round is not digital silence (the frame before it fades out across it). With PNS-coded audio a fill (or any lost frame) gives every later noise-filled band different noise, so later samples are not bit-identical, though nothing moves. The record names what the reading cannot rule out (`timingCaveats`: `whole-round-loss-undetectable`, `fill-may-be-a-repeated-frame`, `unmarked-streams-dealt-in-turn`) and whether the file marks its other streams (`streamMarking`); for a `stream-0-only` file on the split route the queue warns that a missing or repeated frame would put every later frame in the wrong channel unseen. The split reads no further than the inspection did, so a recording still being written converts as inspected (`grewWhileRead`). A file with AVIX segments is not split. A file DepoAudio cannot read, or in which it finds no complete round to split, goes to the native decoder as it is when that is present (`source.trmInspectionError`). Durations come from the frames read, never from an unclosed file's 0x7FFFFFFF length. The export record's optional `source.trm` holds the inspection with `decodePath` (`native-ftr`, `deinterleaved` or `ffmpeg-plain`), `routeReasons`, `inputOptions` and `inputCount`. A synthetic 4-channel fixture with one round per chunk, a synthetic 0x8180 file of two stereo streams, and the rebuild-tool sample (245 760 silent samples per channel) each decode to bit-identical samples by both routes with FFmpeg 6.1.1; with two rounds per chunk that FFmpeg's native decoder wrote an M4A about half as long without an error, which is why such files are split.
- FTR queue notices: an open-ended file says "This recording's header says it was never closed (or is still recording); DepoAudio read the audio written so far."; a signed one "This recording carries a signature: signed (not verified). DepoAudio does not check signatures."; MP2/MP3/WMA audio names its codec; a refused file shows the refusal. Queued chunks with the same folder and location in the canonical FTR name, on the same or consecutive dates, are sorted by the FILETIME in their names and cut into recordings at the avih boundary flags (0x20000000: no earlier file may be joined; 0x40000000: no later file may be joined); once all are read, a recording whose earliest queued file has no start boundary says "The earliest queued file of this recording has no start-boundary mark, so FTR would accept earlier files before it; if there are any, add them too." (and the same for the latest file and the end boundary). A `.trs` session list is not queued; a notice asks for the FTR chunks instead (unchanged).
- Liberty / BIS Digital DCR (experimental; `dcr.rs`, `docs/DCR.md`; layout from owner-supplied interoperability notes, not yet confirmed against a recording made by the vendor's software): DepoAudio's own reader checks the header, version (major ≤ 27), chunk directory (its size must match the file; entries must lie inside the file and not overlap) and chunk framing, reads the audio description (the `meta` XML from version 21.00 — UTF-8 unless it declares windows-1252, hex in either case, `%i` integers read back as 32 bits, 64-bit values and FILETIMEs as two-half child elements — or `wfmt`/`chnl` before it), and walks the data chunk with bounded buffers. Footer chunks are optional. It writes a temporary WAV feed in the private work folder (`workdir.rs`): PCM 8/16/24/32-bit, A-law and mu-law blocks interleave byte for byte into one multichannel WAV; IMA ADPCM, GSM 6.10 and MP3 get one mono WAV per channel (`fmt ` is the stored one-channel WAVEFORMATEX, with `fact` where computable) joined by FFmpeg `amerge` in channel-bit order into a 16-bit PCM WAV, whose guessed speaker mask is then cleared. Conversion reads a DCR feed with `-guess_layout_max 0`, so a kept WAV names no speaker positions (FLAC cannot say that and uses its own layout for the channel count). Probes, Scan, the waveform and conversion all read that feed. The reader's result is reused while the file's path, size and modification time stay the same, so the recording is walked once for the queue and once more to write the feed; Scan and the waveform still demux (and merge) the whole recording although they measure only part of it, the queue probe cannot be cancelled, and free disk space is not checked first. The three stored checksums (41-weight wrapping byte sums over everything before `data`, an empty `data` chunk, and everything after `data`) are verified and reported as `checksums match` / `checksums do not match`; a mismatch is a queue warning and does not stop reading. Redactions in the `mark` chunk (bookmark type `IDMARK >> 28`: 13 begins, 14 ends; positions in samples per channel, kept in milliseconds) are applied by default with no option to ignore them: each begin pairs with the next unused end at or after it, an unpaired begin runs to the end, an end with no begin is ignored with a notice, overlaps are joined with the strictest action (skip > black > play); skip (`<play_skip>`, `<play_omit>`, or no tag) leaves every channel's audio out, black (`<play_black>`, `<play_empty>`) and distort (`<play_dist>`) write silence, play keeps the audio; every atom that overlaps a segment in time is covered. The queue says, for example, "2 redacted segments: 1 left out, 1 silenced, as marked in the recording." and how much shorter the output is; the export record lists `redactions` and `timing`. Audio after `audi#crp` (password protected) is never decoded: it is silence of the same length and the queue warns. Other bookmarks are counted by type. A `prot` chunk gets a warning. The `rinf` session start and the time-zone offset go into the export record as stored, with the UTC-or-local question stated. Tested with synthetic files and the owner's two rebuild-tool tones (`scripts/fixtures/dcr/vendor-notes-samples/`), with FFmpeg 6.1 from PATH: 16-bit PCM in every mode (Keep Original to WAV and FLAC); IMA ADPCM, GSM 6.10 and MP3 (merged feeds) in Split, Keep Original and Mix to Stereo; A-law, mu-law and 8-, 24- and 32-bit PCM in Split only; the plain tone converts to 12.000 s with channels Judge and Witness, and the redacted tone is silent from 4.000 to 6.000 s on both channels and otherwise identical to the plain one; Scan's loudness pass and the waveform decode run with FFmpeg from PATH on a merged IMA ADPCM feed (not through the app's commands). Release builds check that the bundled FFmpeg has these decoders and `amerge`, but the bundled sidecar has not converted a DCR. Split outputs and the export record use the channel names from the recording, without control or invisible format characters (such as direction overrides and zero-width spaces). Video frames and attachments are skipped and counted; no attachment is ever extracted. A remote participant joining (`ptch#str`) adds the bits of the record's `ac` mask to the recorded channels and leaving (`ptch#stp`) removes them (`ac="0"` changes nothing; the record text is read as UTF-16 when it looks like UTF-16, otherwise as Windows-1252); an absent channel is silent so channels stay time-aligned. Refused before anything is written: Speex and unknown codec tags (named), more than 16 channels, a `ptch` record without a readable `ac` attribute in its first 4096 bytes, a redaction begin without a position, a `mark` chunk with text but no bookmark list, more than one `data` chunk, GSM 6.10 or MP3 recordings with participant changes, protected sections or redactions (no known silent block), a recording whose every atom is skipped, and audio out of step with the channel layout (a short last atom after a participant change, or a record marker inside an atom). A last run of bytes too short for one sample of every channel, with no participant change before it, is left out, shown in the queue row and recorded as `trailingBytesDropped`. Case, docket, registration and password fields in the XML, bookmark notes, speakers and attachment names, and the text of participant records, are never kept in the result, logged or recorded; tests seed each of them and check results, queue answers, errors and export records.
- ★ Audio stream: every ffprobe call, Scan and auto-level pass, waveform decode, merge decode and conversion reads the first audio stream explicitly (`-select_streams a:0`, `-map 0:a:0`, split filtergraph input `[0:a:0]`; `SOURCE_AUDIO_STREAM` in `helpers.rs`). The export-record probe and the queue probe list every audio stream (`-select_streams a`) so they can count them, and read the converted stream as the first entry. The fade-out start comes from a decoded-length pass (`decoded_length_args`: the same inputs, decoder and `-map 0:a:0`, or the `amerge` of an FTR recording's channel files, `DECODED_LENGTH_FILTER` counting samples at 48 kHz), never from a stated duration, and the export record keeps both in `processing.fadeOut`; for an SGMCA it is the joined timeline of every session read, decoded from the same concat input the conversion uses. Durations for the WAV size estimate and progress are the converted stream's own (`duration`, or the Matroska `DURATION` tag), falling back to the container duration only when the stream has none. FFmpeg's automatic selection is never used: it prefers a track marked default, then the one with the most channels, which can differ from the stream the probes and the export record describe. A queued file with more than one audio track names the converted track in its row. An SGMCA is described in the queue by its own reader (ffprobe cannot read the Direct Audio layout): its channel count, joined duration, how many recording sessions it holds ("This file holds 3 recording sessions; they are joined in order (gaps between them are not kept)."), which sessions and how many bytes are not read ("The last session (3) could not be read: its header says 0 bytes. 12.3 MB after it were not read.") and whether it looks still recording.
- Export record: each output is reserved together with `<output>.depoaudio.json` (both `create_new`; a taken name moves both to the next numbered name), and the record holds file names only, source and output SHA-256, app version, the exact filter chain, `-map` arguments (`processing.mapArgs`) and encoder arguments, channel and label, the converted audio stream with the source's audio stream count (`audioStream`), the WAV header written (`output.wavHeader`), and the start time. If the record cannot be written, the conversion fails and its outputs are removed.
- Start time: a BWF `bext` TimeReference from a WAV source (the `wav` demuxer, RF64 included; tags in other containers are ignored) is rescaled to the output sample rate and written to WAV outputs with `-write_bext 1`. Every other output gets `-metadata time_reference=`, which removes the tag FFmpeg would copy unrescaled into FLAC, MP3 and Opus, so the start is then in the export record only. Leading-silence trim (not split mode) moves the start, so it is then recorded as not carried and the output has no start tag.
- Learned processing flags are compatibility-only wire fields. Any request with `denoise`, `enhance`, or `dereverb` set fails before file preparation or decode.
- Analysis and auto-level use at most a 180-second representative sample; every sidecar call has a timeout and a kill path (the fix for the scan-hang bug, PR #52).

## Release / update channel

- GitHub Actions `release.yml` creates one commit-bound private draft, builds universal macOS and Windows installers sequentially, stages reviewed FFmpeg inputs, proves zero learned-model/ONNX Runtime payloads, generates and normally decodes a transient synthetic 440 Hz FTR-tagged fixture with the exact candidate sidecars, and uploads only through an exact-draft verifier. `scripts/ftr-smoke-fixture.mjs` keeps the fixture and derived outputs under the runner's temporary directory and removes them before packaging; artifact inventories still reject every `.trm` file. Tauri's action is build-only and has no release mutation credentials.
- Updater artifacts are generated only when the configured private/public keys cryptographically match. Platform signing is enabled independently when that platform's credentials are present; otherwise the workflow produces an ad-hoc-signed macOS app or unsigned Windows installers. Updater key/endpoint configuration is generated only inside the release job; local builds contain neither placeholders nor a live update endpoint.
- Existing published asset names and bytes are immutable. The candidate workflow may reuse only one empty same-tag draft already bound to the exact source commit and retaining the canonical name, changelog notes, and prerelease state; it rejects stale, populated, altered, or duplicate drafts instead of deleting them, never modifies a published release, and finalizes only by auditing the complete private draft. The audit receives the release access GitHub requires to read a private draft, but the release contract rejects mutation commands in that job. The workflow canonicalizes Tauri's updater archive to the versioned universal release name before hashing and upload. It deliberately rejects `latest.json`; updater metadata and publication require a separate approval gate bound to the exact release ID, source commit, assets, signing decision, and release date.
- `publish-release.yml` separates read-only candidate-manifest inspection from protected publication. Its publication path checks out the immutable approval commit, re-downloads and verifies the complete candidate and evidence inventory, cryptographically validates signed updater artifacts, records both source and approval commits, verifies the owner's signed release tag at the source commit (it never creates or moves a tag), and publishes only the approved release ID. The `release-publication` environment's 24-hour wait timer and `main`-only deployment policy, and the tag ruleset that protects `v*` tags, must be verified in GitHub because repository source cannot prove dashboard policy; the workflow reads them back and fails closed.
