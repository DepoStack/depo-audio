# Changelog

## [Unreleased]

## [1.2.0] - Unpublished

DepoAudio 1.2.0 is the first release since 1.0.2. It includes everything that was prepared for 1.0.3 and 1.1.0. Neither of those versions was published, so there is no 1.0.3 or 1.1.0 download.

### What this release includes

A short summary for court reporters, scopists and agencies. The detailed entries follow.

**Formats**

- DepoAudio now reads DigitalCAT / SoundSync `.dm` and Liberty / BIS Digital `.dcr` recordings itself, splits FTR recordings that FFmpeg cannot read on its own (and keeps their start time), and reads and writes CATalyst's SGMCA Direct Audio files with every recording session. These four are **Preview**: they follow interoperability notes and have been tested with sample files made from those notes, not with recordings from the vendors' own software. Check the output before you rely on it.
- In `.dcr` recordings, marked redactions are applied (left out or silenced, as marked) and password-protected sections come out silent.
- Audio is taken from older deposition video files (`.mpg`, `.vob`, `.ts`, `.mts`, `.m2ts`, `.wmv`, `.asf` and similar); the picture is discarded.
- Closed formats such as DS2, Webex and Sony recorder files are recognized, and DepoAudio says which program to export them to WAV with.
- WAV files over 4 GiB get a valid header, and FTR `.tll` files are accepted.

**Player and proofing**

- The Player has three panes: playlist and bookmarks, the transcript in the centre, and Now Playing with the listening tools.
- Proof an existing transcript (SRT, WebVTT, or a CAT ASCII/TXT export with time stamps) against the audio: follow along, jump to any line, nudge the sync, and flag lines for review with a note. Flags export as CSV or text.
- Listening tools: Backstep after a pause, a volume control, and Separate channels with Mute, Solo and a volume for each microphone. These change what you hear only, never the converted files.
- Playback keys can control the Player while you type in another program (off until you turn it on).
- Compare a converted file with its original at the same position.

**Safety for legal audio**

- Every converted file gets an export record next to it (`<output>.depoaudio.json`) with the source and output hashes, the exact settings, and the recording start time when there is one.
- Conversions keep the audio in place: no added delay, no lost first syllables after leading silence, no channels folded away, and always the same audio track the record describes. A conversion that would move or drop audio is refused with a message instead.
- Temporary audio copies go in a private DepoAudio folder that only your user account can read (on macOS and Linux) and is cleared at every launch.
- Settings → Your data shows where DepoAudio keeps its data, and lets you back up, restore, or clear all of it. Nothing is uploaded and no account is needed.

**Fixes**

- Settings sections scroll to the end, Fade no longer silences recordings whose stated length is too short, Mix to Stereo no longer flips loud peaks, re-export from the Library asks before replacing the queue, and many smaller fixes listed below.

**Removed**

- The transcript editor: transcripts are now proofed in the Player, and written and edited in your CAT or transcript software. Transcripts you saved in 1.0.1 or 1.0.2 still open read-only and stay in backups.
- Learned-model ("AI") processing: noise removal, clarity enhancement, room-echo reduction, speaker estimation and quality scoring are gone, and no model files ship. Local AI is planned for v2.

**Security and installing**

- No exception is configured for any Rust security advisory, and the release goes through a one-person publication path with a 24-hour cancellation window and a signed release tag.
- The installers are not code-signed. macOS and Windows warn the first time you open DepoAudio.
- 1.0.2 cannot update itself: download 1.2.0 and install it over 1.0.2. Your library, settings, saved transcripts and bookmarks are kept. Later versions can always be downloaded from GitHub Releases; DepoAudio installs an update itself only when that release carries a verified update signature.

### Added

- **FTR recordings that FFmpeg's FTR decoder cannot read are converted by splitting their channels first. (Preview)** DepoAudio now reads each FTR recording (`.trm`, `.ftr`, `.tll`) through before using it (64 KiB at a time, about once per pass however small its chunks are; the file is never changed). When every audio chunk holds exactly one round of frames starting at channel 0, the file has a usable index, was closed, and no frame needs repair, it still goes to FFmpeg's native `ftr` decoder as before. Otherwise, for example when frames run across chunks, a chunk starts mid-round or holds more than one round, frames are lost or out of channel order, there is padding or unreadable data, the index is missing, or the file was never closed or was cut off, DepoAudio writes each interleaved stream to its own temporary AAC file (undoing FTR's byte scrambling, clearing two frame-length header bits FTR ignores, and keeping every channel the same length) and FFmpeg joins them back in channel order. More than one round per chunk is sent to the split route because, on a synthetic file with two rounds per chunk, FFmpeg 6.1.1's native decoder exited without an error but wrote an M4A about half as long as the audio. The same split happens if the native decoder fails a conversion, a Scan (every channel), a waveform or a merge or sync decode. The channel marker is checked on every frame: when a frame is lost or repeated, the partial round is dropped and dealing restarts at the next channel-0 frame instead of shifting every later frame to the wrong channel, and the export record counts it (`channelResyncs`, route reason `channel-order-resynced`). A recording still being written is converted as far as it had been read when it was queued (`grewWhileRead`). A file whose index was never closed is no longer reported as cut off. A file that continues in further RIFF (AVIX) segments is reported and is not split, since only its first segment would be read. If DepoAudio cannot read a file's layout at all, or reads it but finds no complete round of frames to split (for example a recorder that marks its streams differently from the notes), and FFmpeg has its native decoder, the file goes to that decoder as before, and the export record gives the reason in `source.trmInspectionError`. Keep Original, Split Channels and Mix to Stereo all work on both routes. The temporary files are kept in a new folder of their own for each conversion, with a random name, inside DepoAudio's private work folder (see below); on macOS and Linux the folder and the files can be read and changed by your user account only, so another user of the same computer cannot read the decoded audio or swap a channel file before FFmpeg reads it. The folder and files are removed afterwards; any left by a run that was killed or crashed are removed with that run's folder at the next start or by "Clear all DepoAudio data". The export record has a new optional `source.trm` object with what the reading found, `decodePath` (`native-ftr` or `deinterleaved`) with the reasons, and the options FFmpeg read each input with (`inputOptions`, `inputCount`). The layout DepoAudio reads comes from the owner's interoperability notes. It has been tried with synthetic files built from FFmpeg-encoded tones and with one sample made by the owner's rebuild tool (not by FTR); on those with one round per chunk, FFmpeg 6.1.1's native decoder and the split-channel route produced the same samples bit for bit, and each channel kept its own tone. No real FTR recording has been converted this way.
- **`.tll` files are accepted as FTR recordings**, in the file picker, the Supported formats table (in the app and in the README), Library folder scans and session ordering, like `.trm` and `.ftr`.
- **The Convert queue says when an FTR recording's header says it was never closed, and when a queued recording's boundary marks leave room for files that are not queued.** Such a recording says: This recording's header says it was never closed (or is still recording); DepoAudio read the audio written so far. Its duration, the WAV size estimate, the fade-out position and the waveform now come from the audio actually written instead of the placeholder length in its header. Queued chunks with the same folder and location in their FTR names, recorded on the same or consecutive dates (so a session that runs past midnight stays together), are put in recording order (by the time in their names) and cut into recordings at FTR's boundary marks: a start boundary means FTR joins no earlier file to that one, an end boundary that it joins no later file. Once each has been read, if a recording's earliest queued file has no start-boundary mark, that row says: The earliest queued file of this recording has no start-boundary mark, so FTR would accept earlier files before it; if there are any, add them too (and the same for the latest file and the end-boundary mark). The marks are read as the interoperability notes describe them, which has not been checked against a recording made by FTR. Chunks with other names are not grouped. A `.trs` session list is still not queued and still asks for the recording chunks instead. Each queued FTR file is read through once for this (at most 4 at a time), so for a large session the notices and the size estimate can take a moment to appear.
- **FTR recordings are read as the owner's latest interoperability notes describe them. (Preview)** The format tag's high bits now decide how the microphones are interleaved: 0x4180 means one mono stream per microphone, as before; 0x8180 means stereo streams of two microphones each, which DepoAudio now splits into one stereo file per pair and joins back in channel order (stream k holds channels 2k and 2k + 1), or hands to FFmpeg's native decoder when the layout allows (on synthetic stereo-stream files FFmpeg 6.1.1's native decoder and the split route gave the same samples bit for bit, in channel order). FTR AAC (0x180) with neither bit is refused with: This FTR recording's format isn't one FTR's own player can split, so DepoAudio does not convert it (the queue shows it too); before, such a file was split as if it had mono streams. A file whose frames carry a different channel count than its tag declares is reported and not split. MP2, MP3 and WMA audio in an FTR file is handed to FFmpeg as ordinary audio, with a message naming the codec if FFmpeg cannot decode it. The export record's `source.trm` gains optional fields: `audioCodec`, `streamLayout`, `streams`, `channelsPerStream`, `formatSampleRate`, the audio stream header's scale, rate and chunk count (informational), `avih` `dwStreams` next to the number of stream lists actually present (which is what counts), `startUtc` and `startLocal` from the TUTC and TLOC chunks with `startBasis`, `recordedFileName` from the FILE chunk (only when its text is a file name in the recorder's own format, `<name>_YYYYMMDD-HHMM_<16 hex>.<ext>` with the recorder's character set and a date and time matching the FILETIME; any other text is never copied, and `recordedFileNamePresent` says the chunk holds text), `userNamePresent` and `userDataPresent` (any USER or UDAT chunk with text anywhere in it counts, so a later empty duplicate does not hide an earlier one; the USER and UDAT text itself is never recorded, logged or shown), `signature` ("signed (not verified)" when SIGN/CERT chunks follow the index; DepoAudio neither checks nor writes signatures), and `frameChannelMismatches`. `sessionFirst` and `sessionLast` are renamed `startBoundary` and `endBoundary` (never released). Level-meter chunks and everything after the index are skipped and no longer count as truncation. The new decode path value `ffmpeg-plain`, index kind `not-read` and route reasons `not-ftr-aac` and `frame-channels-differ-from-header` are added to the schema.
- **An FTR recording's start time is kept. (Preview)** The time of day from its TLOC chunk (local time, as a BWF time reference counts it) now goes into a WAV output's bext time reference, rescaled to the output sample rate, as a BWF source's start already does; other output formats keep it in the export record only. A recording with no TLOC chunk takes its start from its TUTC chunk (UTC) or failing that the time in its FILE chunk's name (time zone not stated); since a bext time reference counts from local midnight, such a start is kept in the export record only and no WAV output carries it (`writtenToOutput` false, and the note says why). `startTime.source` says which (`ftr-tloc`, `ftr-tutc` or `ftr-file-name`). Before, FTR outputs carried no start time.
- **Damaged FTR recordings lose less audio, and the export record says what was lost. (Preview)** An index that lists fewer audio chunks than the recording holds (or a different count than its header) is no longer trusted: DepoAudio reads the chunks straight through the audio list, as FFmpeg does, when that finds more, the file is not sent to the native decoder, and the record says so (`indexMismatch`, route reason `index-misses-audio-chunks`); before, the duration, fade-out position, WAV size estimate and split could cover only the indexed part. When reading a file without a usable index meets an unreadable chunk header, a gap of zeros or a chunk written without its pad byte, it now looks up to 4 MiB ahead for the next audio chunk and carries on instead of stopping there, and counts each place (`walkGaps`, `walkGapBytes`). Where a round of microphone frames is damaged or incomplete mid-recording, DepoAudio now fills the same length in every channel in its place with AAC frames that add no new sound (an empty spectrum, 1024 samples per round, for each round the frames there show to be missing) instead of dropping it, so audio after it keeps its time from the start and every channel stays the same length. The export record lists each place (`silenceFilled`: `atSample`, `samples`, `channels`, `reason` `missing-frames` or `unreadable-data`; `silenceFilledGaps`, `silenceFilledSamples`), the duration counts the filled stretches, `startTime.note` says so, and the Convert queue says, for example, "2 damaged sections were filled to keep the timing, adding no new sound (the sound just before each fades out across it); see the export record." Nothing is put in after the last whole round. Where unreadable data was skipped, how much audio it held is not known, so only the rounds the frames around it show are filled and `startTime.note` still says later audio may be earlier by an unrecorded amount. Frames missing in a run as long as a whole round leave no trace in the frames, so such a loss is still not counted or filled; a repeated frame looks the same as a lost one and is filled, and audio after such a fill plays later than its time by the fill's length. The export record now names these limits for every FTR AAC file read (`timingCaveats`: `whole-round-loss-undetectable`, `fill-may-be-a-repeated-frame`) and `startTime.note` repeats them where something was filled. A filled stretch is not digital silence: the decoder fades the audio before it out across it (still at a good part of its level in the stretch's second half), and fades the audio after it in. In a recording coded with perceptual noise substitution (PNS), a fill or any lost frame also gives every later noise-filled band different noise, so later samples are not bit-identical to an undamaged recording, although no audio moves. A file whose frames mark only the first stream is split by taking frames in turn, so a lost or repeated frame there cannot be seen and would put every later frame in the wrong channel: the export record says when a file was read this way (`streamMarking` `stream-0-only`, caveat `unmarked-streams-dealt-in-turn`), and when DepoAudio's own split is the route the Convert queue says: "This recording marks only its first stream's frames, so DepoAudio splits it by taking frames in turn: if a frame is missing or repeated, every later frame goes to the wrong channel and DepoAudio cannot tell. See the export record." (`timelineShiftSecs`, added earlier in this release, is gone; `droppedRounds` still counts the incomplete rounds.) These were tried with synthetic files and with edited copies of the rebuild-tool sample, not with damaged recordings made by FTR.
- **A sample FTR file made by the owner's rebuild tool (not by FTR) is in `scripts/fixtures/trm/vendor-notes-samples/`** with its hex report. Tests check that DepoAudio reads its fields as the report gives them (4 channels, 16 kHz, 15.360 s, start 2026-01-01 09:00:00 UTC), sends it to FFmpeg's native decoder, gets the same samples from the split route, and carries its start into a WAV output. It shows that DepoAudio reads the layout the notes describe, not that FTR's own recordings are laid out that way.
- **Liberty / BIS Digital `.dcr` recordings can be converted (Preview).** DepoAudio now reads DCR recordings itself (see `docs/DCR.md`) and converts them to Mix to Stereo, Keep Original and Split, where each output is named after the channel name stored in the recording ("Ch N" where it has none; invisible formatting characters such as direction overrides are removed from the name). The queue row lists those names and says they replace the channel labels for that file. The layout comes from owner-supplied interoperability notes and has not been confirmed against a recording made by the vendor's software; it has been tested with synthetic files and with two synthetic tones the owner made with a rebuild tool (committed under `scripts/fixtures/dcr/vendor-notes-samples/`), converted with FFmpeg 6.1 rather than the bundled FFmpeg: 16-bit PCM in every mode; IMA ADPCM, GSM 6.10 and MP3 in Split, Keep Original and Mix to Stereo; A-law, mu-law and 8-, 24- and 32-bit PCM in Split only. Each release checks that the bundled FFmpeg has the decoders and the channel-merge filter these need, but does not convert a DCR with it. The original is never changed: the audio is copied into a temporary WAV, which is removed afterwards. A kept WAV names no speaker positions, since the channels are microphones. Video frames and attachments are skipped and never extracted. **Redactions marked in the recording are applied:** a segment marked to be skipped (the default when it names no action) is left out of every channel, so the output is shorter; one marked to be blacked out, or to have its video distorted, is silent; only one marked to play is kept. There is no option to ignore them. The queue row says, for example, "2 redacted segments: 1 left out, 1 silenced, as marked in the recording." and how much shorter the output is; a redaction end with no beginning is ignored with a notice, and a redaction without a position stops the conversion, as does a bookmark section, or any bookmark in it, that DepoAudio cannot read to its end (it could hold the start of a redaction), or a recording with more than one bookmark section. A redaction covers every block it touches: positions go from samples straight to blocks, with no rounding to milliseconds. Times in an IMA ADPCM or GSM 6.10 recording come from its samples per block, not from the stored byte rate, which IMA ADPCM writers often only estimate; one whose samples-per-block count does not match its block size is refused. Each conversion, Scan, Auto-level and waveform reads the recording again rather than reusing what the queue read, so a file replaced by one of the same size and modification time is never converted with the old redactions. **Password-protected sections are silent** in the output, at their full length, and the queue warns: "This recording has password-protected sections; they are silent in the output." When a remote participant joins or leaves, the channels the participant's record names are added or removed, and every channel stays on the same timeline with silence where a channel had no audio. The recording's three checksums are checked; the queue and the export record say "checksums match" or "checksums do not match" (a mismatch is a warning, and the recording is still read). A protection section DepoAudio cannot read is warned about. If the last few bytes of audio are too few for one sample of every channel, they are left out, and the queue row and the export record say so. Refused with a message before anything is written: Speex audio, unknown codecs (the message gives the codec tag), a remote-participant record DepoAudio cannot read, recordings with more than one audio data section, GSM 6.10 or MP3 recordings that need silence written or audio left out, and damaged files. The export record has a new optional `source.dcr` object with the format version, codec, channel names, counts of skipped video frames and attachments, the participant changes, the checksum result, bookmark counts by type, the redactions as applied (`startSecs`, `endSecs`, `action`, `applied`; no note text), how much shorter the output is when audio was left out, the length of any silenced protected audio, and the session start time and time-zone offset when the recording stores them (the start time is written as stored, since it is not known whether the recorder stores UTC or local time). Case, docket, registration and password fields, bookmark notes, speakers and attachment names in the recording, and the text of participant records, are never kept in DepoAudio's results, logs or export records. Scan and the waveform still copy the whole recording into the temporary WAV first, so on a long recording they take a while to start; Scan and Auto-level show "Reading the recording" meanwhile, and are no longer taken for stalled while it runs. The 15-minute limit per file in Scan still applies.
- **DigitalCAT / SoundSync `.dm` files are read, not passed to FFmpeg (Preview).** FFmpeg cannot open a `.dm`, so before this a `.dm` conversion failed. DepoAudio now reads the audio out of the `.dm` into a temporary WAV, the same way it handles an SGMCA, and conversion, Scan and the waveform all read that copy; the `.dm` itself is only read. Blocks are read in file order, as the owner-supplied notes say SoundSync's player reads them, and blocks marked as recorded over (stamp 0) are never in the audio. A queued `.dm` says when blocks were skipped (for example "12 recorded-over blocks skipped.") and when its time stamps go backwards ("Time stamps go backwards in places; the file does not say why. Audio is kept in file order."): the notes say a record-over appends its new blocks with later stamps, so it is not offered as a cause; DepoAudio only sees that a stamp is lower than the one before it, not why. A `.dm` that does not start with the expected header is marked as not recognized ("This .dm file's header isn't one DepoAudio recognizes"), and so is one whose format size does not match its format or whose format fields do not fit what FFmpeg's decoder for that tag needs (see "Checks" in `docs/formats/dm.md`); samples per codec block are counted from the block alignment as FFmpeg's decoders count them, not from the header's samples-per-block field, with a warning when the two disagree. A block that claims more bytes than remain is treated as the incomplete last block whatever length it claims. Reading stops at the first block shorter than the others, which is where the notes say SoundSync's player stops. That block's whole codec blocks are kept, since a short block is the end of an imported WAV rather than deleted audio, and the queue says the notes say SoundSync's player does not play it. If the file goes on after a short block, the rest is not read and is not in the audio, because SoundSync finds blocks (including the ones it marks as recorded over) by their fixed spacing, which a short block breaks; the queue says so ("A short block comes before the end of the file. The format notes say SoundSync's player stops there, and so does DepoAudio: the 4220 bytes after it are not converted."), a warning in the export record names the block, and `bytesAfterShortBlock` gives the size left out. A `.dm` that ends partway through a block, as a recording or copy that did not finish can, keeps every complete block before that point: the incomplete block is left out, the queue says so, and the export record gives its size in `truncatedTailBytes`. A file with no complete block, or a block whose stated length is longer than the block size, gives an error instead of output. Audio over 4 GiB is refused. The export record has a new optional `source.dmTimeline` with the audio format, the block counts, whether a short last block was cut to whole codec blocks (a short last block that was recorded over is counted only as recorded over), what was left out after a short block or an incomplete block, and segments that start where a stamp jumps by more than 2 seconds or goes backwards, each with its first sample and its first block's stamp in UTC (`firstStampUtc`) exactly as stored: the notes say a recording stamps about the end of each block and a WAV import about the start, and the file does not say which made it. Stamps have 1-second resolution and nothing from them is written into the audio. When a SoundSync marker file (`.bmf`, the `.dm`'s name with `.bmf` for the extension, letter case ignored) is beside the `.dm`, DepoAudio reads its `FileInfo` stream and records only counts in `dmTimeline.markerFile`: the entries, how many carry text, how many SoundSync would keep, and how many point at the stamp of a block that was read, with the file's name and size. No hash of the `.bmf` is recorded, since the file is mostly its marker text, and a `.bmf` name that is a link is not followed. Marker text is never kept, logged or written to the record, and there is no option to include it yet; a `.bmf` that cannot be read is reported and never stops a conversion. The layout comes from owner-supplied notes that have not been checked against a file SoundSync itself recorded (`docs/formats/dm.md`), so the format stays Preview: it has been tested only with synthetic files (PCM; GSM 6.10 made by FFmpeg's libgsm encoder, compared sample for sample with decoding the same GSM directly; and a GSM test tone with a `.bmf` that the owner made with their own tool from the same notes, whose decode equals the owner's decoded WAV sample for sample, 23040 samples, with FFmpeg's `gsm_ms` decoder). Release builds now also check that the bundled FFmpeg on macOS and Windows has the GSM, Microsoft ADPCM, IMA ADPCM, A-law and mu-law decoders. The release smoke reads synthetic PCM, A-law, mu-law and ADPCM `.dm` fixtures with its own JavaScript copy of the layout, not with `dm.rs`, and gives the sidecars the WAV it makes; it also gives them the WAVs `dm.rs` wrote for five committed `.dm` fixtures (`scripts/fixtures/dm`: GSM with the SoundSync default header, IMA ADPCM with a short block before the end followed by a cut-off block, MS ADPCM, mu-law and 8-bit PCM). A cargo test fails if `dm.rs` stops writing those exact WAVs, and the smoke's self-test fails if its JavaScript copy gives different bytes. The bundled FFmpeg has not run these checks yet; FFmpeg 6 on Linux decodes all five without error.
- **DS2, Webex and Sony recorder files are recognized and explained.** Adding a `.ds2` (OM System / Olympus DSS Pro), `.arf` or `.wrf` (Webex network recording), or `.msv` or `.dvf` (Sony IC recorder) file no longer gives "Unrecognised file format". The file is marked as a closed format, Convert stays off while it is in the queue, and the message names the software to export it with: ODMS for DS2 (an encrypted DS2 also needs its password there), the Webex Recording Converter for ARF and the Webex WRF2WMV Converter for WRF (both Windows only), and Sony Digital Voice Editor for MSV and DVF, which Sony no longer offers for download. These names come from OM System, Cisco and Sony support pages, cited in `helpers.rs`. DepoAudio does not try to open or decrypt any of these files.
- **Audio from older deposition video files.** `.mpg`, `.mpeg`, `.vob`, `.ts`, `.mts`, `.m2ts`, `.wmv` and `.asf` files are handled like `.mp4`: the audio track is converted and the picture is discarded. The original file is not changed. Each release now makes a small synthetic file for each of these containers (with MP2, AC-3 or WMAv2 audio) and checks that the bundled FFmpeg on macOS and Windows decodes its audio and writes audio-only WAV (plain and with `-rf64 auto`) and M4A, with the same `-map 0:a:0` and output arguments the app uses; a check keeps that list equal to the app's. The macOS build also checks that the WMA 9 Pro, WMA Voice, DVD LPCM and Blu-ray LPCM decoders are present, but no file with that audio is converted at release. A `.ts` file with no MPEG transport stream sync pattern in its first 16 KiB, such as a TypeScript file, is not recognized. A capture that was cut mid-packet or starts with a short header is still recognized. So far they have been tried only with synthetic files on a standard FFmpeg build. The bundled FFmpeg has not run this check yet, and no recording from a deposition video system has been tried.
- **Playback keys while typing elsewhere (off by default).** Settings → Playback keys can let chosen keys control the Player while another app, such as CAT software or a word processor, is in front: Play/Pause, Back (the Player's Backstep, or 2 s when Backstep is Off), Forward 2 s, Slower and Faster. Nothing is registered until you turn the setting on. "Use suggested keys" fills in F13, F14 and F15 for Back, Play/Pause and Forward; they avoid the keys Express Scribe (F4, F7 to F10) and Case CATalyst audio (Shift+F9, Ctrl+F9) use by default, and the section names those uses if you pick one of those keys. The key recorder accepts a function key, or another key only together with Ctrl or Cmd. It refuses letters, numbers and Space on their own or with only Shift or Alt; Escape; lock and media keys; Alt+F4 and Ctrl+F4; Ctrl+Alt without Cmd or Win, because on Windows that is AltGr, which types characters such as @ and € on many keyboards; Ctrl or Cmd with arrows, Backspace, Delete, Insert, Home, End, Page Up, Page Down, Enter, Tab or Space, which still edit, move the cursor or switch apps; Ctrl or Cmd with A, C, S, V, X, Y or Z, with or without Shift (copy, paste, undo, redo, save); and Cmd+Q and Cmd+W. Ctrl or Cmd alone with B, I, U, F, P, N, O or W is allowed with a note that word processors and CAT editors use it. On Windows and Linux a letter is stored by the letter your keyboard layout gives, because that is how those systems register it, and a punctuation key that gives a different character than on a US layout is refused. A warning says that while the setting is on these keys are taken from every app. Each key is registered on its own, and one the system refuses shows a plain message next to it (for example, that another app is already using the key), with the system's own text under "System message"; some systems do not report a key another app already holds, and the section says so. Keys are released when you turn the setting off, while the recorder is listening and when the app quits; they stay registered while a DepoAudio text field has focus, so an assigned key does not type there either. A key held while keys are released and registered again no longer ignores its next presses for up to 10 s. Hold to play makes the Play/Pause key play while held and pause when released, the press-and-hold pedal behavior; the next press resumes with the Player's Backstep. With the Player tab closed or no recording loaded, a key does nothing and a line in the sidebar says why. When a key could not be registered, the sidebar line says how many (for example "Playback keys on: 1 key not registered, see Settings"), so the failure shows outside Settings too. The Change, Assign, Clear and Use suggested keys buttons are 44 pixels high, and Clear is drawn as a bordered button with more space between it and Change. A foot pedal in keyboard mode can use these keys if its setup tool can send the assigned key; Infinity IN-USB pedals need a helper app to send keys, because DepoAudio does not read pedals directly yet. Hold to play needs the pedal or helper app to send a key release, and the Foot pedals section says to use Press to play or pause if the Player keeps playing after the pedal is lifted. This uses the Tauri global-shortcut plugin 2.4.1, which on macOS registers keys through the system hot-key service (not an event tap). It has been tested with unit and component tests and a stubbed plugin only, not yet on a real Mac or Windows PC, with a pedal, or alongside CATalyst or Eclipse. On Linux the plugin supports X11 only.
- **The Player can rewind a little when you resume.** With Backstep on, pressing Play, Space or K after a pause first goes back the chosen number of seconds so the last words are heard again. Backstep is Off until you choose 1, 2, 3 or 5 seconds in the Backstep menu next to the transport, so playback does not change after updating; the choice is saved like playback speed, and screen readers read the rule as the menu's description. In a window narrower than 760 pixels, the track name and scrubber move to their own line under the transport buttons, so the name is not cut to a letter or two. Seeking, changing tracks and the A-B loop wrapping do not rewind, the rewind never goes before the start of the track, and inside an active A-B loop it never goes before the loop start.
- **The Player has a volume control and can separate a file's channels while you listen.** A Volume slider in Now Playing sets the playback level; it is saved like playback speed and starts at 100%, so playback sounds the same after updating. For a file with 2 or more channels, a Separate channels button shows a strip per channel (Ch 1, Ch 2, ...) with Mute, Solo and a 0–200% volume slider. Up to 4 strips sit two to a row; with more channels the strips are narrower and four fit across, so 16 channels take four rows. Every button and slider in the mix is at least 44 pixels high. The slider tracks have a border in the secondary ink and fill in ink up to the value; from the theme tokens, the border is about 10:1 against the card in light and dark (WCAG 1.4.11 asks for 3:1); this was checked from the token values, not measured in a screenshot. With any Solo on, only soloed channels are heard; a muted channel stays silent even when soloed; a strip that is silenced says Muted or Silent (solo). A status line above the strips, also read out by screen readers, says how many channels are heard once anything is muted or soloed (for example "Hearing 1 of 16 channels") and says when every channel is silent. Reset channels stays in place (it does nothing while every strip is at its default), so keyboard focus is not lost, and the status line confirms the reset. A 2-channel file keeps its left and right; with 3 or more channels every channel plays in both ears, and the heard channels share the level: each is played at 1 divided by the number of heard channels, so four microphones picking up the same voice sound as loud as one instead of four times louder and clipping, and a soloed channel plays at its own level. With every strip at 100%, a file whose channels carry different speakers can therefore sound quieter than normal playback; Solo or a strip's volume brings one channel up. These controls change what you hear only: converted files and exports are not affected, and the Player says so next to them. Strips start at 100% for each track and are not saved; when the previous track had a Mute, Solo or volume change and the next track starts (including by auto-advance) with Separate channels still on, the status line says "New track: the Mute, Solo and volume settings from the previous track were cleared. Every channel is heard at 100%." Turning Separate channels on or off keeps the position, speed and play state, and the A-B loop and Backstep work the same: if you turn it on or off while paused, the next Play still goes back by Backstep, and a Play/Pause press (button, Space or a playback key) or a Back or Forward playback key press made before the new playback has loaded is applied once it has. The playback keys from Settings (Play/Pause, Back, Forward, Slower, Faster and Hold to play) act on the mix the same way; that was checked in component tests with a stand-in for Web Audio, not in the app. If the web view will not open the file for Web Audio, the Player goes back to normal playback and says why. Once the mix has opened a file, a later track the web view cannot decode gets the usual "Couldn't decode" message and Separate channels stays on for the next track. If Web Audio is still paused after playback starts (for example a play from a playback key that the web view does not allow without a click), the Player goes back to normal playback and says why instead of playing with no sound; a context WebKit reports as interrupted is resumed too. Playback from a playback key relies on Tauri's default autoplay setting, and the release checks now fail if `tauri.conf.json` sets `additionalBrowserArgs` or turns autoplay off. These paths were checked in component tests with a stand-in for Web Audio only. When the web view passes fewer channels to the Player than the file has, the strips are labelled as the web view's mix and the Player says how many it can separate, pointing to Split Channels in Convert; any Mute, Solo or volume set on the file's channels before that was found is cleared, and the status line says so, so a Solo on a channel that is no longer shown cannot silence playback. If the next track has 1 channel, or its channels cannot be counted, the Separate channels button stays so the mix can be turned off, no strips are shown, and a note says why. This was tried in Chromium (the engine behind Windows WebView2) with synthetic 4- and 8-channel WAV files served from another origin with CORS, as Tauri's asset protocol does: all 4 and 8 channels reached the Player, and Solo, Mute and the volume sliders changed the measured output as expected. The level sharing was checked by rendering the same graph offline in Chromium: four or six identical channels at half scale summed to 2.0 and 3.0 (clipped) at unity gain and to 0.5 with the shared level. The 2-, 4- and 16-channel layouts were checked in screenshots at 1160×820 in light and dark; the down-mix case was checked in unit tests only, because Chromium passed every channel. It has not been tried in the app itself, in WebView2, or in the macOS web view. On macOS it depends on the web view accepting the CORS header Tauri's asset protocol sends for `asset://` files, which has not been checked; if it does not, every attempt goes back to normal playback with the "could not start" message; WebKit's source passes up to 32 channels, but that has not been checked with a file.
- **Compare a converted file with its original.** "Compare with original" on a converted row opens a small player with Original and Output buttons that switch between the two at the same position. It needs a source the app's web view can play: for .sgmca, .trm and .ftr sources the button is struck through, can still be reached with the keyboard, and is followed by "(unavailable: Original can't be played here; open the output in Player.)". For split conversions it compares the first output, names it, and notes that the original plays all of its channels together. After Trim silence, the output starts later in the recording than the original, so the player says positions do not line up instead of promising the same position. If the original or the output cannot be opened when you play it, the player says so; for the output it suggests Reveal in folder and another player.
- **SGMCA is read, checked and written natively (Preview)** (`src-tauri/src/sgmca.rs`, documented in [`docs/SGMCA.md`](docs/SGMCA.md)). The layout comes from owner-supplied interoperability notes and has not yet been confirmed against a file CATalyst wrote: a 40-byte file header, then one segment per recording session, each a 56-byte header with the session's local start time and byte length, followed by a complete Ogg Opus stream (mapping family 255, or 1 from CATalyst's import, with one uncoupled mono stream per channel). `sgmca_inspect_cmd` walks every segment and page (capture pattern, sequence, CRC) and reports each session's channel layout, pre-skip, start time and exact duration from its last granule position minus pre-skip, naming the segment, page and byte of any damage. **Convert can now write SGMCA**: libopus, mapping family 255, 20 ms frames, encoded at 48 kHz as the notes say CATalyst's own encoder runs (earlier builds encoded at 16 kHz, which kept nothing above about 8 kHz), 32 kbps per channel, in Keep Original, Split Channels (one Direct Audio file per channel) and Mix to Stereo; each output is read back and removed unless it has the Direct Audio layout, and its export record says `sgmca`. A slice that copies Opus packets without re-encoding (80 ms decoder pre-roll, exact pre-skip, end trim, rebased granules, fresh CRCs) is in the module and tested, but not yet on screen; it refuses a cut that runs from one recording session into the next.
- **Every converted file gets an export record.** DepoAudio writes `<output>.depoaudio.json` next to each output. It holds the source and output file names (never folders), their SHA-256, the app version, the exact FFmpeg filter chain and encoder settings, the channel and its label, and the recording start time when the source has one. A record never replaces an existing file: if the output or record name is taken, both move to the next numbered name. If the record cannot be written, the conversion fails and its outputs are removed rather than delivered without one. The format is published as `docs/export-manifest.schema.json`. Hashing reads each file once more, so large conversions take a little longer.
- **The recording start time is carried through.** When a source WAV has a BWF `bext` start time, WAV outputs get their own `bext` chunk with the same start, rescaled to the output sample rate. FLAC, MP3, Opus and M4A have no such chunk, so their start is kept only in the export record. With leading-silence trim on, the first sample moves by an amount FFmpeg does not report, so the output carries no start time and the record says the output start is not known.
- **Settings → Your data shows where DepoAudio keeps its data.** It lists the app data folder (with a button to show it) and each DepoAudio file in it with its size, and counts the saved transcripts and bookmarks. It says that recordings, converted files and export records stay where they were saved, that nothing is uploaded and no account is needed, and that DepoAudio does not encrypt these files itself, so full-disk encryption should be on. [`docs/LOCAL-DATA.md`](docs/LOCAL-DATA.md) documents every location.
- **Back up and restore the library and transcripts.** Export writes a new `.zip` (never replacing a file) with the case library, transcripts, bookmarks and a README; it holds no audio or settings and is not encrypted, and the app says so. Import reads only an unmodified DepoAudio backup and only adds: cases match by name and sessions by ID, a transcript is restored only where this computer has none for that track, and bookmarks are added unless already present. The result lists what was added, what was kept, and which Library files are not on this computer.
- **Clear all DepoAudio data.** After a confirmation, it removes the library, settings, interrupted-save files and model files left by an older version from the app data folder, and DepoAudio's saved transcripts, bookmarks and preferences, then reloads the app as on first launch. Recordings, converted files, export records and backups stay. It is not available while files are converting. It also recovers from a damaged library, which otherwise leaves the Library read-only.
- **The app version is shown in Settings and on the recovery screen, with "Copy diagnostics".** It copies only the app version, operating system and processor type, FFmpeg version and, on the recovery screen, the error type. Error messages, file names and folder paths are never included. The exact text is shown before it is copied, and nothing is sent: you choose where to paste it.
- **Interface failures have a recovery screen.** If the interface hits an unexpected error, a recovery screen explains what happened and offers a reload, without uploading diagnostics, file names, recordings or case information.

The transport bar stays at the bottom. Each pane scrolls inside itself, so the window no longer scrolls at 1160×820 and larger. Drag the splitter between panes, or focus it and use ←/→ (Home/End for the smallest and largest size), to resize a side pane, or hide it with the button in its header; the sizes are remembered on this computer (`player-layout` in the app's web storage, cleared by Clear all DepoAudio data). The centre always keeps at least half the width while the side panes are above their minimum. In windows narrower than 1100px the side panes become drawers opened from buttons above the transcript (Esc closes them). With no transcript loaded, the centre explains what proofing does, lists the formats it opens and has the Open transcript button. All keyboard shortcuts work as before.
- **The Player's transcript panel is now for proofing an existing transcript against the audio; editing transcripts is left to your CAT software.** "Proof a transcript against this recording" opens an SRT, WebVTT or text file with time stamps, including CAT ASCII/TXT exports with `[HH:MM:SS]` or `HH:MM:SS` line stamps (with or without line numbers), and says what it found, for example "42 timed lines; times look like time of day". You can change whether the times are time into the recording or time of day. Each line keeps its page and line number from a CAT file, shown beside it (for example 12:4); rows holding only a page number or a line number with no text are not listed. The line at the playhead is highlighted and, with Follow audio on, kept in view; when the keyboard focus is on a line, it moves with the playing line, so pressing F flags the line you are hearing. Moving through the lines with the keyboard pauses following ("Follow audio paused") until playback starts again, you play a line, or you press . (period) or Back to playing line. Click a line or press Enter on it to play from its time, and use the arrow keys, Home, End, Page Up and Page Down to move between lines. The line list gets the rest of the window's height, and at least 40% of it, so a short window scrolls a little rather than showing only a few lines. If the transcript is ahead or behind, nudge it by 0.5 s or use the button that sets the current line to now, which names the line it changes (for example "Set page 12, line 4 to now"); the shift is shown as "Transcript is ahead by 1.5 s", saved for that track, and changes only when you change it. For time-of-day stamps, DepoAudio asks for the time the recording started, because the Player does not read a recording's start time yet; it does not guess. A stamp up to an hour before that start is kept before the start of the audio rather than moved to 0, so a sync shift can still correct a CAT clock that runs behind the recorder. A stamp earlier than that, or more than 12 hours after the start (for example a 12-hour clock stamp), cannot be placed: the line says so when you try to play it, instead of playing from the start. The mapping code can join multi-session recordings end to end and send a time that falls between sessions to the start of the next session, as CATalyst does, but the Player has one start time only, so it maps every line against one session: for a recording paused over lunch, lines after the break are off by the length of the pause. Press F on a line (or click its flag) to flag it for review with a short note; which line was flagged is shown next to the Flags for review heading. Flags never change the transcript text, and Export flags saves them as CSV or text (page and line number from the file when it has them, row in DepoAudio's list, audio time, time of day when known, excerpt, note) through a save dialog. Typing into transcript lines, stamping new lines, starting a transcript from scratch, pasting text, and SRT/TXT export are gone. Transcripts saved by earlier versions, including ones typed in DepoAudio, still open in the panel, read-only, with their times read as time into the recording; Copy with times (which replaces Copy text) puts each line on the clipboard after its time, to the millisecond, so those timings can still be taken out. Backups carry them as before, now with any flags. "Remove this transcript from DepoAudio" deletes only DepoAudio's stored copy, its flags and its sync settings; it asks first, and so does opening another file over a stored transcript. Sync settings are kept per track under `transcript-sync:<track path>` in web storage, removed by Clear all DepoAudio data, and not included in backups.
- **The sidebar no longer shows FFmpeg and update status.** "FFmpeg ready" and "Up to date" are gone from the bottom of the sidebar; the "Powered by DepoStack" credit stays. When the audio engine check fails (FFmpeg or FFprobe missing, the FTR decoder check failing, or the check itself not running), Convert and Player show a warning that says what is affected and what to do, with Re-check and Engine details buttons. It can be dismissed for the session and comes back at the next launch or the next failed re-check until the engine is fixed; conversions that need the missing piece still fail in the backend as before. Settings has a new About section with the FFmpeg version, the FFprobe and FTR decoder checks, a Re-check button, the update state in one line, and Copy diagnostics.
- **Temporary audio copies now go in a private DepoAudio folder that is cleared at every launch.** The copy of an SGMCA with a vendor prefix, the WAV read out of a `.dm`, the WAV decoded from a `.dcr` (and the one-channel WAVs its channels are joined from), an FTR recording's split channel files and Merge's working WAVs used to go in the system temporary folder. They now go in a folder of their own for each run, under `work` in DepoAudio's cache folder. On macOS and Linux that folder and the files in it can be opened only by your user account (folder mode 0700, files 0600); on Windows the cache folder's own per-user permissions apply. Each run keeps a lock on its folder while the app is open; the lock file is locked before it appears, and if something outside the app deletes it (for example a cache cleaner), it is made and locked again the next time a temporary copy is needed. At launch, and when you choose Clear all DepoAudio data, folders whose lock is free (left by a run that has closed or crashed) are removed, and a folder another open DepoAudio is using is left alone. A folder that has no lock file is removed only once nothing in it has changed for a day. A lock that cannot be checked is left alone and listed in the Clear all DepoAudio data warning. If the disk cannot lock files, the run goes ahead without a lock and its folder is left alone by other windows. Copies that earlier versions left in the system temporary folder (`depoaudio_` followed by a random id, ending `.wav` or `.sgmca`) are removed by the same step only when no other DepoAudio window holds a lock and the copy has not changed for a day, so an older DepoAudio version that is still open (it holds no lock) keeps the copies it is using. On macOS and Linux, copies that belong to another user account are left alone. Clear all DepoAudio data now clears these leftovers after it has reset the library and settings, off the main thread. Removing a held lock file and renaming a locked one have not been checked on Windows. Temporary copies are no longer forced to disk with a sync, since only the run that wrote them reads them. DepoAudio's cache folder on macOS is under `~/Library/Caches`, which Time Machine skips by default, so no exclusion attribute is set; that has not been checked on a Mac. Merge, which is still hidden, also gets a cancel flag that stops source copies, FFmpeg and ffprobe; there is no Cancel button for it yet.

Before, FFmpeg could map a video file's picture into an M4A output as a video stream. Cover art in an MP3 source is no longer copied to an MP3 output either.

The Audio processing panel now says so before a scan and next to its results, and that anything later in a long recording is not measured. The number comes from one frontend constant that a test keeps equal to the backend's sample length.

### Fixed

- **SGMCA conversions refuse to drop, add, delay or move audio, and say what a crashed recording left out.** An SGMCA output made from an SGMCA source must now hold exactly the source's samples, and each recording session exactly its own; an SGMCA output of any other source must hold exactly the samples of the source (read from a PCM WAV's data chunk, or counted by decoding the source once before converting; a source at another rate than 48 kHz may come out one sample longer from rounding, never shorter); otherwise the output is removed and the message gives both counts. A last 20 ms Opus frame that is only partly audio is kept on FFmpeg 6.1 and 8.0. Mix to Stereo without Normalize Volume added a limiter that delayed every sample by 5 ms and cut the last 5 ms, in every output format, while the export record said the timeline was kept; the limiter now compensates its look-ahead (`latency=1`), and a conversion chain with any filter not measured to keep the audio in place is refused, in every format. M4A made from a Direct Audio SGMCA file started 312 samples (6.5 ms) late with a lead-in, because FFmpeg read the sessions' concat script as starting before zero; the input is now moved back by exactly that pre-skip, and a test checks the position of clicks in every output format and mode. A page timestamp that ends before its audio on any page but a session's last (end-of-stream) page is refused: FFmpeg would play those samples, so every later session would be late and the end lost while the sample counts still matched. Trim Leading Silence is refused on an SGMCA file with more than one recording session, because the sessions' boundaries and start times could no longer be placed in the output. A second Ogg stream inside a recording session is refused instead of being skipped without a word. When the last session of a still-recording or crashed file, or bytes at its end, are not read, the queue now says so before converting ("The last session (3) could not be read: its header says 0 bytes. 12.3 MB after it were not read.") and the export record keeps the same facts in `source.sgmca.unreadBytes` and `omittedSegments`.
- **SGMCA reading no longer drops later sessions, or refuses files CATalyst is said to accept. (Preview)** A segment whose length was 0 or stopped short of its pages, followed by another session, used to end the walk there: the later sessions were silently left out of conversions and their export records. DepoAudio now refuses such a file and names the bytes. A newest session that held only its first header pages (the normal state just after recording starts) made the whole file fail; it is now left out with a note, and the earlier sessions are read. A segment header's version and kind, which the notes say CATalyst does not check, and a different Opus output gain on a later session, are now named in a note instead of refused. A page timestamp that jumps past its audio, or overflows, is refused instead of being taken as the session's length, and a file whose sessions hold no samples gets DepoAudio's own message instead of FFmpeg's. The two sample files from the owner's notes (synthetic tones made by the owner's tool, not by CATalyst) are now committed and tested.
- **SGMCA outputs always carry a start time CATalyst can read, and keep every source sample.** A source segment whose start text did not parse was copied unchanged and passed the self-check; such an output now takes the time of conversion, and the export record says why. The header holds whole seconds, so a BWF start between two seconds is written as the whole second at or before the first sample, and every source sample is kept: the export record gives the fraction in a new `output.sgmca.startOffsetMs` field and in the note ("CATalyst stores whole seconds; this recording's first sample is 0.42 s after the time written."). No source audio is ever left out to make the time round; the writer refuses any plan that would. The library slicer cuts exactly where it is asked, writes the whole second at or before the cut, and reports the fraction the same way.
- **SGMCA files with more than one recording session lost every session after the first. (Preview)** A Direct Audio file holds one Ogg Opus stream per recording session, each behind its own segment header, but DepoAudio looked for one Ogg stream in the first 8 KiB and stopped at its end, so every later session in the file was left out with no message, and the segment start times were never read. DepoAudio now reads the 40-byte file header (size 40, version 1; any other value is refused with what was found), walks every segment by its stored length, checks each session's stream page by page, and joins the sessions in file order. The Convert queue says so for a file with more than one: "This file holds 3 recording sessions; they are joined in order (gaps between them are not kept)." Every session must have the same channel count, or the file is refused with both counts named. Sessions in mapping family 255, family 1 (what CATalyst's import is said to write) and family 0 are read. A file that looks still recording or cut short (its last session shorter than its header says, or bytes after it that no header counts) is read up to its last complete page, and the queue and the export record say so. FFmpeg reads each session in place from the original file through a small temporary concat script, so no copy of the audio is made. A file that starts with `OggS` (what earlier DepoAudio builds wrote) is still read, as one session with no start time. The export record has a new optional `source.sgmca` object: the file version, whether the header carries a recording identifier (the identifier itself is not recorded), each session's start text, local start, UTC offset, first sample in the joined audio, duration, channel count and mapping family, and the still-recording and older-layout flags. Tested with synthetic files only, including a three-session file of different tones whose conversion holds exactly every session's samples in order; no file CATalyst wrote has been tried.
- **SGMCA files DepoAudio wrote lacked the Direct Audio header CATalyst expects.** The writer produced a bare Ogg Opus stream. According to the notes, CATalyst refuses to open a file whose first four bytes do not give a 40-byte header, and when recording into such a file renames it and starts a new one. Each SGMCA output now starts with the file header (version 1, a fresh random identifier) and one segment per recording session with its local start time (`YYYY-MM-DDTHH:MM:SS±hhmm`) and exact length, then the Ogg Opus stream with the same encoder settings as before. The start time comes from the source's own SGMCA segment headers (a source with several sessions gives an output with the same sessions, each cut from the encoded stream at its own start without re-encoding), else from a BWF source's date and bext time reference in whole seconds with this computer's UTC offset, else from the time of conversion, which is not when the recording was made; leading-silence trim always gives the conversion time, because it moves the start by an unknown amount. The new optional `output.sgmca` object in the export record says which, with a note, and lists the segments as read back. Every output is read back and removed unless it has the header, complete segments with the planned start times and one mono stream per channel. CATalyst has not opened one of these files yet. The local UTC offset comes from the operating system; only the Linux path was run here, and the Windows path was not compiled here.
- **Fade no longer silences most of a recording whose stated length is too short.** The fade-out was placed from the length the file's headers state. A file that holds two Ogg streams one after the other states only the last one's length: a 15 s recording in two parts (10 s and 5 s) stated 5 s, so the fade-out started at 4.5 s and everything after 5 s, two thirds of the recording, came out as digital silence, while the export record showed only the fade filter. A VBR MP3 without an index can state an estimate in the same way. With Fade on, DepoAudio now decodes the recording once (the same decoder and track as the conversion) and counts its samples, and places the fade-out that far from the start. If the length cannot be measured, nothing is converted and the message says to turn Fade off or try again. The export record has a new `processing.fadeOut` object with the fade-out's start and length, the decoded length it was placed from, and the length the headers state, so a difference between them is on record. On a single-part SGMCA the fade-out used to end about 7 ms after the audio because the stated length counted the Opus pre-skip; it now ends at the last sample. Each release checks that the bundled macOS and Windows FFmpeg can run this exact counting filter.
- **Keep Original no longer writes MP3, M4A or Opus that lose channels.** For a source with more than two channels, FFmpeg's MP3 encoder folded the channels into stereo (on a 4-channel WAV the fourth channel disappeared and the third was mixed into both sides), and AAC coded the fourth channel of a 3.1-layout WAV, the layout a 4-channel WAV often has, as a low-pass bass channel, so a 1 kHz voice on it came out at -73.6 dB instead of -9 dB. The export record still said all channels were kept. Keep Original to MP3, M4A or Opus now converts only mono and stereo recordings; anything more is refused before an output is written, with a message that points to WAV, FLAC or SGMCA, or Split Channels. Convert says so under the format tiles while Keep Original and one of these formats are selected. The sample-alignment test now uses the 3.1 layout as written and expects these refusals, instead of relabelling its source as 4.0 and accepting a 2-channel MP3.
- **Mix to Stereo shifted the audio about 5 ms later and cut the last 5 ms; outputs now line up sample for sample with the source.** With Normalize off, Mix to Stereo adds a peak limiter so loud overlapping channels do not clip. FFmpeg's limiter looks 5 ms ahead and, by default, outputs that lookahead as a delay while keeping the length the same, so about 5 ms (239 samples at 48 kHz) of silence was added at the start and the last 5 ms of the recording was lost. The limiter now runs with `latency=1`, which removes the delay. Each release also runs the exact limiter and trim filters on the bundled macOS and Windows FFmpeg, and a check keeps those strings equal to the app's.
- **Trim silence no longer cuts the first 0.3 s of speech.** Trim silence asked FFmpeg for 0.3 s of sound before it stopped trimming, and FFmpeg 6.1 and newer drop that 0.3 s along with the silence, so the first 0.3 s of sound after leading silence was removed. Its 20 ms RMS window also ended the silence a few samples late. Trim now stops at the first sample above the silence threshold on any channel (`detection=peak:window=0`), so only audio below the threshold is removed. A single click above the threshold during the leading silence now ends the trim there, so more of the start can be kept than before. The export record still says that trim moved the start but not by how much.
- **Mix to Stereo no longer flips loud peaks upside down.** On a 16-bit source, FFmpeg mixed the channels in 16-bit integers, so when the weighted sum of the channels went past full scale (a channel turned up in the mixer, or auto-level gains, on overlapping loud speech) it wrapped around to a large peak of the opposite sign before the limiter saw it. The mix now runs in floating point (`aformat=sample_fmts=fltp` before `pan`), so the sum keeps its value until the limiter, or loudnorm when Normalize is on, brings it under full scale.
- **A test converts a click-and-tone file through every mode, processing option, format and sample rate Convert offers** (244 conversions on system FFmpeg) and checks that every output channel has the source's length at the output rate, shortened only by Trim silence and only by silence, and that its clicks sit at the source's sample positions. M4A is checked against the length its edit list states, because AAC codes 1024-sample frames and FFmpeg decodes the last frame's padding after that length. The same checks run on a DigitalCAT `.dm` source and on an SGMCA source with two recording sessions, whose outputs must hold both sessions' samples with each click in its session and a fade-out placed at the end of the joined timeline.
- **A file with more than one audio track is converted from the track its export record describes.** The probes, the waveform and the export record always read the first audio track, but conversion, Scan and auto-leveling let FFmpeg choose a track. FFmpeg prefers a track marked default and otherwise the one with the most channels, so a video with a mono floor track and a 4-channel interpreter track could be converted from the interpreter track while its record described the floor track. Every FFmpeg and ffprobe call now names the first audio track (`-map 0:a:0`). A queued file with more than one audio track says so in its row, for example: This file has 2 audio tracks; converting track 1 (eng, "Floor"). The other track is not converted. The export record has a new `audioStream` object with the converted track's index and the number of audio tracks in the source. Choosing another track is not available yet. An SGMCA file has one audio track; its row instead says how many recording sessions it holds.
- **WAV outputs over 4 GiB get a valid header.** WAV output always used a plain RIFF header, whose size fields stop at 4 GiB, so a longer file was written with a broken header (a 16-channel 48 kHz Keep Original WAV passes 4 GiB after about 46 minutes). A WAV whose estimated size reaches 3.5 GiB, or whose size cannot be estimated, now gets FFmpeg's `-rf64 auto`: it stays plain RIFF while it fits, with a small reserved JUNK chunk before the format chunk, and gets an RF64 header once it passes 4 GiB. Every other WAV keeps the same plain RIFF layout as before, with no reserved chunk, so programs that expect the format chunk straight after the RIFF header still read it. The export record has a new `output.wavHeader` field, `riff` or `rf64`, read from the finished file itself. The `bext` start time is written the same way under both headers. Some older programs cannot open RF64 files. With WAV selected, Convert shows an estimated output size for the queue, worked out as duration × channels × sample rate × 2 bytes, and says when an output will pass 4 GiB. The RF64 path was tested with FFmpeg's `-rf64 always` on a small file, not by writing a 4 GiB file.
- **Opus output now says that older CATalyst cannot play it.** The earlier Quick Share preset made Opus files without saying so. Choosing Opus, by preset or by hand, now shows that Stenograph says Opus plays only in CATalyst 20 or newer, and that its audio association article lists .opus files. The Opus preset's name no longer names a CATalyst version, because Stenograph gives that version for playback only.
- **The phone preset describes what it does.** It said "focused speech-band filtering", but it only turns on the high-pass filter (80 Hz unless changed in Settings) and loudness normalization. It now says exactly that.
- **Fade-out and the WAV size estimate use the converted track's length.** The duration probe read the container's length, which is longer than the first audio track when a video runs past its audio or a second track is longer. On a file whose first track ran 4 s inside a 10 s container, a 2 s fade-out was placed at 8 s, past the end of the track, so no fade-out was applied, and the WAV size estimate counted 10 s. The probes now use the converted track's own duration (or its Matroska DURATION tag), and the container's only when the track has none.
- **The export record has the `-map` that picks the converted track.** `processing.encoderArgs` was described as including stream selection but did not hold the `-map 0:a:0` that Mix to Stereo and Keep Original use, so re-running the recorded command on a file with several audio tracks could convert another track. A new `processing.mapArgs` holds each output's `-map` (`-map 0:a:0`, or `-map [opN]` for a split file's branch), and the encoderArgs description no longer mentions stream selection. The schema now also requires `output.wavHeader` to be `riff` or `rf64` for a WAV and null for other formats.
- **Adding many files no longer starts one ffprobe per file at once.** The queue probe behind the multi-track notice and the WAV size estimate now runs at most 4 at a time, so dropping a folder of hundreds of FTR/TRM chunks does not start hundreds of processes together. A file removed from the queue loses its probe result, and a probe for it that has not started is skipped.
- **Checking a `.ts` or `.dcr` file no longer runs on the main thread.** Format detection reads a few bytes of these files. It now runs on a background thread and skips the read for anything that is not a regular file, so a file on a stalled network share or a named pipe cannot freeze the window while files are added.
- **SGMCA inputs are decoded with libopus. (Preview)** FFmpeg 6.1's built-in Opus decoder turned one channel of a synthetic 16 kHz mapping-family-255 stream (the SGMCA layout) into full-scale noise, while libopus decoded it cleanly. Every bundled FFmpeg includes libopus; the macOS build script now checks for its decoder. The existing SGMCA tests used mapping family 1 (coupled surround), which does not show the problem; they now use family 255.
- **Every Settings section can be read to the end.** Cards in Settings were shrunk to fit and cut off their lower rows (most visibly in Model files and Your data). Each card now keeps its full height and only the content pane scrolls; the section list and the Settings header stay in place, and each section opens at its top.
- **A converted file can be revealed and opened in the Player from its row.** "Show in Explorer / Finder" appeared only when a conversion made several files. Every completed row now has "Reveal in folder", and "Open in Player" when the output is a format the Player opens directly (WAV, MP3, FLAC, Opus, M4A). Open in Player adds the outputs to the playlist and selects the first; split outputs are all added. Each button's accessible name starts with its visible label (for example "Reveal in folder: hearing.mp3"), so voice control can press it by what it says.
- **Re-export from the Library asks before replacing the Convert queue.** Re-export (and queueing a court-software job) used to replace whatever was waiting in Convert without a word. When the queue already has files, DepoAudio now asks "Replace the N files in the queue?" with Replace, Add to queue and Cancel. Add to queue has focus when the dialog opens, so pressing Enter never replaces the queue, and the count stays current if files are added while the dialog is open. Cancel leaves the queue as it was. With an empty queue it fills the queue straight away, as before. Nothing is deleted from disk either way.
- **File-picker failures in the Library are no longer treated as a cancel.** A failed picker now shows a clear error, with technical detail behind a disclosure.
- **The guided conversion steps stay readable at high display scaling.**
- **One file with an out-of-range modified date no longer fails a court-software scan.** A file dated past the year 9999 is left out of the job's date instead of stopping the whole scan.
- **Deleting model files left by an older version only deletes.** Unknown names, folders, links and paths outside the models folder are refused, and no model install or download action remains.

### Removed

Typing into lines, stamping new lines, starting a transcript from scratch, pasting text and SRT/TXT export are gone; write and edit transcripts in your CAT or transcript software, and proof them against the audio here (see Changed). ### Security

## [1.0.0] - 2026-07-16

The first public release. A desktop audio converter and enhancer for court reporters that processes recordings locally.

### Features

- **Conversion** — court formats (SGMCA, FTR/TRM, BWF, DigitalCAT) plus standard audio and video, out to WAV/MP3/FLAC/Opus/M4A; three output modes (mix to stereo, keep original, split by channel) with per-channel labels and volume; batch processing and 5 presets.
