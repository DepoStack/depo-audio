# Changelog

## [Unreleased]

These changes are on `main` but not in the existing private v1.0.3 candidate, which was built from an earlier commit. Whether they ship as a rebuilt v1.0.3 or as a later version is an open owner decision in the release gate.

### Added

- **Every converted file gets an export record.** DepoAudio writes `<output>.depoaudio.json` next to each output as a new file. It holds the source and output file names (never folders), their SHA-256, the app version, the exact FFmpeg filter chain and encoder arguments, the channel and its label, and the start time when the source has one. The source hash is of the original file as selected, before any format preparation. The output and its record are reserved together, so a record never replaces an existing file: if either name is taken, both move to the next numbered name. If the record cannot be written, the conversion fails and its outputs are removed rather than delivered without one. The format is published as `docs/export-manifest.schema.json`, and a test checks real records against it. Hashing reads each file once more, so large conversions take a little longer.
- **The recording start time is carried through.** When a source WAV has a BWF `bext` TimeReference, WAV outputs get their own `bext` chunk with the same start, rescaled to the output sample rate. FLAC, MP3, Opus and M4A have no `bext` chunk. FFmpeg would copy the source's `time_reference` tag into FLAC, MP3 and Opus outputs without rescaling it, so DepoAudio removes that tag and the start is recorded only in the export record. Leading-silence trim moves the first sample by an amount FFmpeg does not report, so with trim on (Mix to Stereo or Keep Original) the output carries no start time, and the record keeps the source start for reference and says the output start is not known. DepoAudio reads a start only from a WAV source's `bext` chunk (RF64 included); a `time_reference` tag in any other format is ignored. The `-write_bext` option and the `time_reference` tag were checked with FFmpeg 6.1.1 on Linux (Rust tests run them when FFmpeg is installed, including one that checks FLAC, MP3, Opus and trimmed WAV outputs carry no `time_reference`); the release sidecars still need the same check in the installed-app pass.
- **The app version is shown in Settings (Updates, About) and on the interface recovery screen, with "Copy diagnostics".** It copies only the app version, operating system and processor type, FFmpeg version and, on the recovery screen, the error type (such as `TypeError`). Error messages, file names and folder paths are never included; each value must match a narrow pattern or is replaced with `unknown`, and a test feeds paths and file names through every field. The exact text is shown before it is copied, and nothing is sent: the person chooses where to paste it. `health_check` now also returns `ffmpegVersion` (the version token from FFmpeg's first output line only), `os` and `arch`.

- **Settings → Your data shows where DepoAudio keeps its data and lets people back it up or clear it.** It lists the app data folder (with a button to show it) and each DepoAudio file in it with its size, and counts the transcripts and bookmarks in the app's web view storage. It says that recordings, converted files and export records stay where they were saved, that nothing is uploaded and no account is needed, and that DepoAudio does not encrypt these files itself, so full-disk encryption should be on. [`docs/LOCAL-DATA.md`](docs/LOCAL-DATA.md) documents every location.
- **Export library and transcripts.** Writes a new `.zip` (never replacing a file) holding the case library, the non-empty transcripts, the bookmarks, a format marker and a README. It holds no audio or settings and is not encrypted, and the app says so.
- **Import a backup.** Reads only an unmodified DepoAudio backup (known stored entries, checked CRC-32, format version 1) and only adds: cases match by name and sessions by ID, a transcript is restored only where this computer has none for that track, and bookmarks are added unless already present. Every case name and Library file entry is checked before anything changes. A restored file is made playable only after symlinks are followed and the target is a regular audio file, the same rule as importing audio into the Library; at startup, Library files are authorized by the same rule. The result lists what was added, what was kept, how many Library files are not on this computer, and, separately, how many are on this computer but need a restart because they were removed from playback earlier in the same app run (for example by Clear all). Closing Settings afterwards reloads the app.
- **Clear all DepoAudio data.** After a confirmation, removes `library.json`, `prefs.json`, interrupted-save temp files and legacy model files from the app data folder, and DepoAudio's own keys from web view storage, then reloads the app as on first launch. Only those exact names are removed: no path recorded in the Library is followed, a symlink with one of those names is skipped, a `models` folder that is a symlink is skipped as a whole (legacy model cleanup in Settings → Model files refuses it too), and recordings, converted files, export records and backups stay. It is not available while files are converting: the button is disabled, and the app refuses if a conversion is still running. A file that cannot be removed is named and the app does not reload. This also recovers from a corrupt library, which otherwise leaves the Library read-only.
- **Delete transcript for this track.** A bin button on the Player's transcript card removes the saved transcript for that track after a confirmation. Exported SRT and TXT files are not affected, and a pending autosave cannot write the old lines back.

### Removed

They stay in git history; the last commit that has them is `ceafc9c`. **Owner action:** to keep them easy to find, tag that commit (suggested name `archive/learned-model-sources`); no tag was created by this change. `npm run models:check` now fails if any of these files returns.
- **The hidden Merge commands are no longer reachable over IPC.** `detect_sync_cmd` and `merge_audio_cmd` are unregistered while Merge stays hidden; `merge.rs` and `MergeTab.jsx` remain on `main` for now and are still unit-tested. The owner decided on 2026-11-13 to move Merge to a branch and return to it when Transcript handles multi-file proceedings; that move is a separate change and has not been made here. The release contract fails if either command is registered again without that decision.

### Changed

- **An empty transcript no longer leaves a storage key.** Opening a track in the Player used to save an empty `transcript:<track path>` entry, which kept the path (and often the case name) in web view storage. Autosave still checks that storage works, then removes the empty entry.
- **Tauri moves to 2.12.** The Rust crates lock Tauri 2.12.5 (`tauri-utils` 2.10.2, `urlpattern` 0.6.0) and the JavaScript packages use `@tauri-apps/api` and `@tauri-apps/cli` 2.12.4. The minimum Rust version is now 1.90, which Tauri 2.12 requires. The WebView2 evidence script now expects CLI 2.12.4; its download paths were rechecked against tauri-bundler 2.10.4 and are unchanged.
- **The updater plugin moves to 2.14.1** (Rust crate and JavaScript package). The updater stays dormant unless a release carries a verified updater configuration.
- **CI also runs weekly on a schedule**, so an expiring exception or a new advisory turns `main` red without waiting for a push. GitHub turns that schedule off after 60 days without repository activity, so the release owner checks that it is still enabled.
- **The Windows app keeps linking the Visual C++ runtime dynamically.** Tauri 2.12's build step would otherwise link it statically into `depo-audio.exe`; `tauri.conf.json` turns that off so the Windows binary is linked as the existing candidate was.
- **One person can complete a release.** The publish workflow no longer requires a second environment reviewer with self-review prevented. It now requires a wait timer of at least 24 hours on `release-publication` that administrators cannot bypass (deploying only from `main`), an active tag ruleset that restricts creating, moving and deleting `v*` tags, and a signed annotated release tag at the exact source commit that GitHub reports as verified and whose tagger is the release owner email recorded in the release gate. The publication helper verifies all three before any release write and no longer creates the tag itself.
- **DepoAudio is named "DepoAudio, powered by DepoStack".** Settings → Updates → About and the sidebar link now say "powered by DepoStack" instead of "part of DepoStack" and "A DepoStack project"; the link's arrow is hidden from screen readers. The macOS app category is now Productivity instead of Music. The bundle identifier, storage keys, updater endpoint and copyright line are unchanged.
- **Text on gold is the DepoStack plum-black in both themes and clears 7:1.** The ink on gold buttons, badges, checkboxes and the Play button moves to plum-black `#20182A` (7.9:1 on the gold fill). The hover gold in both themes is now exactly the brand hover gold (gold.300, `#F0B456`), so hovered text stays above 7:1 (9.3:1) instead of dropping to about 4.8:1 in the light theme; the documented 5.9:1 exception is gone. The dark theme's hover gold had drifted slightly from the brand value (`36 83% 65%` and `#f0b65e`, which also differed from each other) and now uses it too. A test computes these ratios from `design/tokens.json` and checks that the hsl and hex forms of each gold agree. Bundling the brand fonts (Archivo, Fragment Mono) is not part of this change: they would be new third-party files in the release and need a licence and distribution-ledger decision first. The copyright year and the v1.0.0 release notes also wait for the owner.
- **The conversion's planning step is separated from running FFmpeg.** Choosing outputs, building the FFmpeg arguments, and everything after FFmpeg exits (checking the outputs, fingerprinting them, writing their export records and keeping them) are now plain functions that the Tauri command calls, so the tests above drive the same code; the FFmpeg arguments and records are unchanged. Source preparation and the source fingerprint now run in one background task instead of two, and the output fingerprints and records in one background task instead of one per output.

### Tests

- **SGMCA and DigitalCAT `.dm` conversions are tested end to end.** Rust tests build a synthetic 4-channel Ogg Opus stream from FFmpeg sine tones (no speech, each channel at its own level), put a made-up non-Ogg prefix in front of it and name it `.sgmca`; a plain 4-channel WAV named `.dm` stands in for DigitalCAT, which DepoAudio passes to FFmpeg unchanged. No byte of a real Stenograph or DigitalCAT file is used. The tests call the conversion's own request checks, source preparation and fingerprint, ffprobe arguments, filter builder, plan and FFmpeg arguments, and the same output-check, fingerprint, export-record and commit step the app runs, with FFmpeg from PATH. The part that needs the Tauri runtime (the order of the probes and their cancel checks, the auto-level analysis, the sidecar launch and progress events) is mirrored in the test, not shared; a test supplies the auto-level gains the analysis would return. They cover Split Channels (WAV and FLAC) and Mix to Stereo (WAV and MP3), and check the number of outputs, their channel count, sample rate, duration and level (so each split file holds the right source channel), every `<output>.depoaudio.json` against `docs/export-manifest.schema.json`, that the record fingerprints the `.sgmca` as selected rather than the stripped Ogg, that the temporary Ogg copy is removed, that a second run never replaces the first run's files or their export records, and that an SGMCA with no Ogg stream fails before any output exists. Three more cases cover the per-channel processing: Split with four different auto-level gains (each output's level shows its own gain landed on it), Mix to Stereo with a gain on one channel only, plus a 3-channel gain vector that must be ignored for a 4-channel source, and Split with loudness normalization and fades on (still a valid 4-channel filter graph, 48 kHz outputs, fades in place, channels brought within 6 dB of each other). They are skipped with a message when FFmpeg, ffprobe or libopus is missing, except in CI, which installs FFmpeg and sets `DEPOAUDIO_REQUIRE_FFMPEG_TESTS=1` so a missing tool fails the Linux Rust job instead; the export-record FFmpeg tests follow the same rule.

### Security

- **Local data at rest is a recorded exception.** DepoAudio does not encrypt its library, settings, web view storage or backup zips. The compensating control is the operating system's full-disk encryption, which Settings → Your data asks people to turn on (`SECURITY.md`, `docs/LOCAL-DATA.md`).
- **CI scans for committed secrets.** A new `secret-scan` job runs gitleaks v8.30.1 over the full git history on pull requests, pushes to `main` and the weekly run, and prints findings redacted. The gitleaks GitHub Action is not used, because it is under a proprietary licence and needs a licence-key secret for organisation repositories. The MIT binary is built from the Go module version instead, whose hash the Go checksum database fixes, and the job checks that hash again. Every action in `ci.yml` stays pinned to a full commit SHA, and the release contract now fails if one is not. `npm run ci:local` runs the same scan when gitleaks is installed. The full history (195 commits) scanned clean on 2026-11-13.
- **Two incident runbooks:** [`docs/RUNBOOK-BAD-RELEASE.md`](docs/RUNBOOK-BAD-RELEASE.md) (stop new downloads, warn people, replace a release with a new version without changing a published asset) and [`docs/RUNBOOK-SIGNING-KEYS.md`](docs/RUNBOOK-SIGNING-KEYS.md) (lost or compromised updater key, Apple or Windows certificate, or GitHub access). `SECURITY.md` links both.
- **The expired `rust-unic` advisory exception is deleted.** Tauri 2.12 no longer depends on the five unmaintained `unic-*` crates, and `deny.toml` now carries no advisory exception.
- **Rust advisories published after the candidate was built are resolved on `main`:** `rustls` 0.23.46, `rustls-webpki` 0.103.17, `tokio` 1.54.1, and `zip` 9.4.1 (through the updater plugin).
- **Build and test tooling clears `npm audit --audit-level=high`:** `vite` 8.2.4, `vitest` 4.1.12, `postcss` 8.5.32, `eslint` 10.14.0, and patched transitive `undici`, `zod`, `browserslist`, `brace-expansion` and `source-map-js`. None of these is in the shipped frontend bundle. One moderate `minimatch` advisory remains inside `eslint` 10, with no fix that stays on eslint 10.

## [1.0.3] - Unpublished

### Added

- **Unhandled interface rendering failures have an explicit recovery path.** A root-level React recovery screen explains the failure and offers a user-initiated reload without uploading diagnostics, filenames, recording data, or case information.
- **Frontend size budgets and release-target dependency policy now run in CI.** Deterministic JavaScript and CSS limits catch bundle regressions, while Cargo license, source, wildcard, and duplicate-dependency rules cover the macOS and Windows release graph.

## [1.0.0] - 2026-07-16

The first public release. A desktop audio converter and enhancer for court reporters that processes recordings locally.

### Features

- **Conversion** — court formats (SGMCA, FTR/TRM, BWF, DigitalCAT) plus standard audio and video, out to WAV/MP3/FLAC/Opus/M4A; three output modes (mix to stereo, keep original, split by channel) with per-channel labels and volume; batch processing and 5 presets.
- **Smart Cleanup interface** — one-click Scan presents denoise, auto-level, de-clip, clarity, turn, speaker-slot, and quality analysis. Several ONNX-backed paths were not verified in the published v1.0.0 installers and should not be treated as released behavior.
- **Player** — color-coded speakers, 0.5×–2× speed, A-B loop, and editable bookmarks.
- **Library & detection** — case library auto-filed by case and participant (search, archive, re-export); court-software detection (Case CATalyst, FTR Gold, Eclipse, DigitalCAT, CourtSmart) with direct job import.
- **Platform** — universal macOS (Apple Silicon + Intel) and Windows. The published macOS app was ad-hoc signed and not notarized, the Windows installers were unsigned, and the release contained no updater manifest. Recordings remained local; no account or subscription was required.

### Added

- **Live scan progress** — the Convert-tab Scan streams progress for every analysis phase (loudness, noise floor, speech, speaker turns, quality, speakers), the bar advances _within_ each file with a phase label — including heartbeats while a slow FFmpeg pass drains its timeout, so "slow but alive" looks different from "stuck" — and a Cancel button actually stops the backend compute.
- **FTR session chunks auto-order chronologically** — dropping or browsing a set of `.trm`/`.ftr` chunks queues them in recording order (parsed from FTR's filename timestamp, verified against real court-produced files) regardless of how the OS delivered them. Applies to the Convert queue and the Player playlist (newly added batches only — manual reordering is preserved). Mixed selections keep the order you chose.
- **Universal macOS build** — one `.app`/`.dmg` runs natively on both Apple Silicon and Intel. FFmpeg sidecars and the ONNX Runtime library are combined for both architectures; no more separate Intel/Apple-Silicon downloads.
- **Auto-update code path** — the app contains an updater UI and signed-manifest verification path, but the published v1.0.0 assets did not include `latest.json` or updater signatures, so updating was dormant in that release.
- **Player keyboard transport** — Space/K play-pause, ←/→ seek ±5s, J/L seek ±10s, ↑/↓ change speed, [ / ] previous/next track, B add bookmark (ignored while typing in a field).
- **Playback speed** — 0.5×–2× control in the player, persists across sessions (essential for transcription).
- **A-B loop** — set in/out points and repeat a passage for re-listening.
- **Bookmark notes & export** — bookmark labels are now editable (e.g. "Objection", "Exhibit 4") and the whole list copies to the clipboard as timestamped lines for a transcript.

### Fixed

- **Scans finish now — every prior release could hang or freeze** — one fix in three layers. Analysis reads a bounded sample of each file instead of the whole recording (a multi-hour multichannel deposition previously ran tens of thousands of ONNX inferences and effectively never completed), and every analysis FFmpeg pass has a timeout backstop whose expired processes are killed rather than orphaned at full CPU. AI inference moved off the async runtime onto the blocking pool with cancellation checks and wall-clock budgets, so queued scans can no longer freeze the entire app. And a stalled file is skipped after 150 seconds of silence instead of poisoning the whole scan, with failures reported ("2 of 3 files couldn't be analyzed") instead of silently reverting to the idle hint.
- **Scanning FTR (.trm) files always failed** — analysis passes never applied the forced FTR decoder that conversion has always used, so every Scan of a `.trm` file failed or timed out. Scan decodes now handle FTR's proprietary codec, and files that genuinely can't be decoded short-circuit the remaining passes with an honest "convert it first" recommendation. A channel-probe failure also no longer invents four phantom channels of extra work.
- **Model downloads restored** — the `models-v1` release hosting all nine downloadable AI models was deleted during a repository cleanup, so every in-app model download returned 404; it was rebuilt with each asset verified against the app's SHA-256 pins. The real DNSMOS quality-scoring model is now published and integrity-pinned like the rest (the previously committed file was an HTML error page), and its catalog size corrected (0.3 → 1.1 MB).
- **Auto-level gain safety** — conversion only applies per-channel auto-level gains when the analysis measured the same channel count the converter sees, preventing a desynced analysis from boosting some channels and silencing others.
- **App now closes immediately** — closing the window quits the process directly, so an in-flight scan or conversion can no longer leave the app stuck on exit.
