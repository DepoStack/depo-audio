# DepoAudio v1.0.3 release candidate

Status: preparation only; not a published release  
Prepared: 2026-08-24  
Preparation base: `9118c9d3f51637fda54fdfe544f13eaa00574b36`  
Latest verified published release: `v1.0.2`

This document separates a buildable v1.0.3 source candidate from a verified,
downloadable release. Version metadata and change notes may be merged before a
private candidate is built. The private application candidate correctly
reports 1.0.3, while the README published-release badge and website must
continue to describe v1.0.2 until v1.0.3 is published and its assets are
independently checked.

The v1.0.3 changelog heading remains `Unpublished` during candidate work.
Before a final `v1.0.3` build, replace that marker with the actual release date;
the release workflow rejects a final tag while the marker remains.

## Intended scope

- Add an accessible, local-only root React recovery screen for unhandled
  interface rendering and lifecycle failures.
- Enforce deterministic frontend size budgets.
- Enforce Cargo license, source, wildcard, and dependency policy across the
  configured release targets.
- Revalidate the complete npm, Cargo, Tauri, and changelog version contract at
  the start of the release workflow.
- Update `plist` and `quick-xml` to remove `RUSTSEC-2026-0194` and
  `RUSTSEC-2026-0195` from the locked graph.
- Record native, installer, fixture, and model distribution evidence that must
  be reviewed before publication.
- Preserve the v1.0.2 capability boundary. No format, conversion, cleanup,
  model, player, library, Merge, or transcript capability is added.

## Publication blockers

The following are release gates, not optional follow-up work:

- Close every applicable `Evidence required` entry in
  [`THIRD_PARTY_LICENSES.md`](../THIRD_PARTY_LICENSES.md), including notices,
  provenance, immutable digests, and commercial redistribution evidence for
  shipped sidecars, runtimes, installer payloads, and model weights.
- Review the five visible unmaintained `rust-unic` advisories through
  `urlpattern -> tauri-utils -> Tauri`; remediate them or record an approved,
  time-bounded risk acceptance.
- Replace the moving DNSMOS source with an immutable upstream revision.
- Establish permission and provenance for the FTR CI fixture and confirm it is
  absent from every packaged artifact.
- Extract each final MSI, EXE, DMG, and app bundle and reconcile its contents
  against the third-party ledger.

## Private candidate verification

A private `v1.0.3-rc.1` draft may be used to collect evidence. It is not
publication approval. Before promoting a final release:

1. Confirm the workflow ran from the exact intended `main` commit.
2. Record each asset name, byte size, SHA-256 digest, and download URL.
3. Verify Windows 10/11 x64 installation and startup for both MSI and NSIS.
4. Verify macOS 13.3+ startup on Apple Silicon and Intel.
5. Verify Authenticode, Apple signing, notarization, Gatekeeper, SmartScreen,
   updater metadata, and updater signatures from the built assets themselves.
6. Exercise file opening, conversion, playback, library, transcript, and local
   processing on the installed applications.
7. Confirm optional network behavior and that recordings are not uploaded.
8. Replace the generic draft body with release notes grounded in the tested
   artifacts.

Only after the final v1.0.3 release is public and install-smoked should the
website release contract, direct downloads, changelog, structured data, and
published-release badge be updated and merged.
